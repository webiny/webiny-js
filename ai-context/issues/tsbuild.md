# TypeScript Build: Wrong Cross-Package Paths in .d.ts Files

## Problem

When building packages that use TypeScript `projectReferences`, generated `.d.ts` files in `dist/` end up containing wrong relative paths like:

```ts
import("../../api/src").ContextPlugin
import("../../handler/src").BeforeHandlerPlugin
```

Instead of the correct package names:

```ts
import("@webiny/api").ContextPlugin
import("@webiny/handler").BeforeHandlerPlugin
```

This causes downstream TypeScript errors. For example, when `packages/api/src/` gets pulled into the `graphql` workspace TypeScript program via a bad `.d.ts` import, it fails with `TS2307: Cannot find module '~/...'` because the `~/` alias is not configured in that workspace's tsconfig.

## Root Cause

All `tsconfig.build.json` files are **autogenerated** by `scripts/generateTsConfigsInPackages.js`. They include cross-package `paths` entries that redirect imports to `src/` during development, for example:

```json
"@webiny/api": ["../api/src"],
"@webiny/handler": ["../handler/src"]
```

When `ts.createProgram` is called with `projectReferences`, TypeScript applies each referenced project's own tsconfig `paths` when resolving types. It then inlines those resolved paths as relative paths into the generated `.d.ts` files. The result is that `../../api/src` (a raw filesystem path) ends up in the output instead of `@webiny/api`.

**Do not modify tsconfig files** — they are autogenerated and will be overwritten.

## Fix

The fix is in `packages/build-tools/packages/buildPackage/tsAliasReplacer.js`.

This file is a post-processing step that runs after `tsc` emit. It was extended to also replace cross-package relative `src/` paths in generated `.d.ts` files with proper package names.

It works by:
1. Scanning sibling packages in `packages/` to build a map of `absolute/path/to/pkg/src → @webiny/pkg-name`
2. After `tsc` emit, scanning all `.d.ts` files in `dist/`
3. Replacing any `"../../xxx/src[/subpath]"` pattern with the resolved package name `"@webiny/xxx[/subpath]"`

## Verification Script

`scripts/checkDistPaths.js` (in project root) scans all `packages/*/dist/**/*.d.ts` files and reports any remaining bad paths. Run it after a build:

```bash
node scripts/checkDistPaths.js
```

Exits `0` if clean, `1` if bad paths are found.

## Known Limitation

The fix in `tsAliasReplacer.js` uses `path.resolve()` and `path.join()` internally without normalizing to forward slashes. On Windows, the `srcDir + "/"` separator check in `resolveToPackageName` will fail because Windows paths use backslashes. This means the replacement may not run on Windows. **Needs testing on Windows before considering fully resolved.**

## Key Files

| File | Role |
|------|------|
| `packages/build-tools/packages/buildPackage/tsAliasReplacer.js` | Post-processes `.d.ts` files — **this is where the fix lives** |
| `packages/build-tools/packages/buildPackage/tsCompile.js` | Calls `tsc` and then `replaceTscAliases` |
| `scripts/generateTsConfigsInPackages.js` | Autogenerates all `tsconfig.build.json` files — **do not edit generated files** |
| `scripts/checkDistPaths.js` | Verification script — scans dist for bad paths |
