## Review Focus for this sub-phase

Review Focus 2 (an end date lands on the wrong day) and 9 (the admin-ui fix changes other date pickers):

- `parseDateOnlyValue("2026-10-20")` is local midnight of 20 October in a negative-offset zone (`America/New_York`) and in a positive one (`Asia/Tokyo`); the test proves the zone was applied to the test process (UTC parsing of the same string gives the 19th in New York).
- Any value that is not exactly `yyyy-MM-dd` (a full ISO instant, an ISO value with an offset, a local date-time) is still `new Date(value)`.
- Only the `date` case of `formatDateForDisplay` changes; `dateTimeLocal`, `dateTimeTz`, `dateRange` and the other cases are untouched; `DateTimePicker.tsx` is untouched; presets still compare `yyyy-MM-dd` strings and still emit `format(date, "yyyy-MM-dd")`.
- The `minDate` / `maxDate` matcher list is built with `if` statements (code-style "no inline conditional spreads"), produces the same matchers as `DateTimePicker.tsx:131-134`, and is reviewed by reading (admin-ui has no DOM tests; Task 12 renders it).
- No admin-ui `package.json` change, no new dependency (`date-fns` `parse` and the `react-day-picker` `Matcher` type are already available to admin-ui).
