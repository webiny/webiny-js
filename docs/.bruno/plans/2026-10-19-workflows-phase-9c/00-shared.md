# Workflows Phase 9c: Reviewer exclusions and the workflows permission UI

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The workflows feature is finished on the admin side. A viewer with the workflows `editor` permission opens Settings > Workflows > Reviewer exclusions (`/settings/workflows/exclusions`), one page for every app, mounted once by `WorkflowsAdminApp`. The page loads the whole exclusion list (expired entries included) over the existing shared `workflows.getSettings` / `workflows.updateSettings` operations, resolves user names by id ("Deleted user" for missing ones), and shows every entry with Active, Expired and All tabs, a client-side user filter, the reason, the end date in the viewer's local time (with the full time and timezone on hover) and the status. Add, Edit and Remove each save at once from their dialog, sending the whole list from the last load; the last save wins (D106). An end date is the end of the picked local day (23:59:59.999), stored as UTC; editing without changing the date keeps the stored instant. Without `editor` the menu group is hidden and a direct URL shows a no-access view (the editor routes get the same change). The security role form gets a Workflows group with No access / Full access / Custom and the "Manage workflows" (`editor`) and "Reassign and operate" (`reassign`) checkboxes, so `reassign` can finally be granted. The admin-ui `DateOnlyPicker` honours `minDate` and reads `yyyy-MM-dd` as a local date. Dead permission code is deleted and the docs are brought up to date. No API changes.

The use case always sends `includeExpired: true` (a save replaces the whole record, so an unloaded expired entry would be deleted silently; research-api 1). Envelope rule as R204: a server error throws `toOperationError(error)` (`GraphQLOperationError` with `code`, `message`, `data`), a transport failure rethrows the `Error`. User names and the user search reuse the shared `WorkflowConfigUseCases.listUsers` (no settings copy). The domain keeps `reason` and `endsOn` as `string | null` (absent and `null` both map to `null`; `null` is sent back as `null`, which the server turns into an absent key).
- R318. **Saving** (Q62, D106). The page presenter holds the list from the last load or the last successful save. A dialog builds the new list from it with exactly one change (add appends, edit replaces the entry with the same `userId` in place, remove filters it out), sends the whole list with `updateSettings`, and on success hands the returned record to the page, which becomes the new last-loaded list (names resolved only for ids not yet known). There is no re-read before a save and no conflict UI; one dialog is open at a time, so one save is in flight.
- R319. **Dates** (Q63, D43, D73, D110, D124). The viewer's timezone is `Intl.DateTimeFormat().resolvedOptions().timeZone`, or `UTC` when that is empty or throws (`resolveViewerTimeZone`); the same zone is used to compute, to show and to name the zone. A picked day `yyyy-MM-dd` becomes `getEndOfLocalDay(date, timeZone)`: the UTC ISO string of 23:59:59.999 on that day in that zone (offset found with `formatToParts`, re-checked at the result so DST days are right). `formatToParts` has no millisecond part, so `getTimeZoneOffset` truncates the instant to the whole second (`instant - (instant mod 1000)`) before comparing it with the wall time from `formatToParts`; without this the result is off by 999 ms and lands on the next local day. An entry is active while `endsOn === null || Date.parse(endsOn) > now` (the server's `filterActiveExclusions` rule). The earliest pickable day is today in that zone (`getTodayLocalDate(now, timeZone)`), passed to the date picker as `minDate` (local midnight). The Edit dialog pre-fills `getLocalDate(endsOn, timeZone)`; `resolveEndsOn` returns the stored `endsOn` string unchanged when the picked date equals the pre-filled date, `null` when cleared, else the end of the newly picked day. "Pick today or a later date." shows only when the date was changed and is before today (QBZ-30). `now` is read when the VM is computed; the page does not tick (an entry that expires while the page is open moves on the next load or save).
- R320. **Date display** (D124, QBZ-95, Q63). Formats use `en-GB` parts with `hourCycle: "h23"` in the viewer's zone, with fixed month names (R339). Until cell (`formatUntilLabel`): `Until removed` for no date; `End of {d Mon yyyy}` when the local hour is 23 and minute 59; else `{d Mon yyyy}, {HH:mm}`. Hover (`formatUntilTitle`, the cell's `title`): `{Ddd} {d} {Mon} {yyyy}, {HH:mm} {short zone name} ({IANA zone})`, assembled from `formatToParts` (ICU puts a comma after the weekday, the design does not), e.g. `Tue 20 Oct 2026, 23:59 CEST (Europe/Zagreb)`; `Until removed` for no date. With the zone unresolved the zone is `UTC` (`… 21:59 UTC (UTC)`). The short zone name is whatever ICU gives (New York in `en-GB` gives `GMT-4`); tests assert Zagreb exactly and the other zones by the same `formatToParts` call.
- R321. **User names** (Q64, D117, Q68.1, Q68.4). After a load the page collects the distinct `userId`s it has no name for and calls `listUsers({ search: null, ids: chunk, teamIds: null, limit: null })` for each chunk of `USER_IDS_LIMIT` (200) ids, inline in the presenter (no wrapper helper), concurrently, merging the results. A returned user gives its `displayName`; an id in `missingIds` is "Deleted user" (muted, sub line `This user no longer exists`); ids still unknown after a failed call show the raw user id and the page shows the banner `Could not load user names.` with `Try again`, which looks up only the unresolved ids. A `NotAuthorized` code on the lookup switches the page to the no-access view. Each run carries a token; a response of an older run (reload, newer save) is dropped. A user picked in the Add dialog arrives with its summary and is never looked up. Names are not refreshed for ids already known. No avatars and no team sub-lines (Q64).
