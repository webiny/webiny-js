**Goal:** The security role form (and the API key form, which renders the same registered element) gets a Workflows group that grants workflows access the way the design draws it: a `No access` / `Full access` / `Custom` segmented control, and for Custom the `Manage workflows` (`editor`) and `Reassign and operate` (`reassign`) checkboxes with their descriptions, the level notes (QBZ-77) and the always-shown reviewing note. Full access is stored as exactly `{ name: "workflows.*" }`; Custom as one `{ name: "workflows", editor?: true, reassign?: true }` entry that keeps any other keys; Custom with nothing ticked is stored as `{ name: "workflows" }` and reloads as Custom. Legacy `{ name: "workflows.*", editor: true }` roles read as Full and are rewritten only when the admin changes the group. A `*` entry (API keys) reads as Full and locks the group. The element owns only the `workflows` and `workflows.*` entries; everything else passes through in order. `reassign` can finally be granted. In `packages/app-workflows`.

## Review Focus for this sub-phase

Review Focus 5 (the role form writes the wrong shape or loses other permissions) and the role-form part of 6 (the group shows only with the flag):

- **Read matrix** (Task 15): a non-array value is No access; `*` is Full and `locked` (also with `workflows` entries next to it); `workflows.*` is Full with or without `editor: true`; `workflows` entries give Custom with `editor` / `reassign` only for flags `=== true` (`"yes"` is false), several entries combine, an entry with nothing set is still Custom; a name such as `workflows.read` is not owned.
- **Write matrix** (Task 15): Full appends exactly `{ name: "workflows.*" }` (one key); Custom appends one `workflows` entry with the other keys of the first existing `workflows` entry, `editor: true` / `reassign: true` only when ticked and no unticked key; Custom with nothing ticked is exactly `{ name: "workflows" }` and reads back as Custom; No access removes both owned names; every other entry (including `*`) keeps its position and object identity; the input is never mutated; a non-array starts from `[]`; a locked access returns the list unchanged.
- **Level switch and notes** (Task 15): Custom from No access is unticked, from Full both ticked; Full and No access drop the flags; same level and locked come back unchanged; the four notes are verbatim R333 and one ticked box has no note.
- **Element** (Task 16): `onChange` is never called on mount (also for a legacy `{ name: "workflows.*", editor: true }` and for `*`), not when the active level is clicked again, and not while locked; each user action writes the Task 15 value; no `aacl` alert and no `useAuthentication` (the element renders with no identity at all); the checkbox descriptions are linked by `aria-describedby`; the level control is labelled `Access level` (Copy gap 1).
