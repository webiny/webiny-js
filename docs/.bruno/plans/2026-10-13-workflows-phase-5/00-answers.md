# Phase 5 open questions: answers (2026-10-13)

- Q1 trigger/save ordering: (a) trigger inside reach before save, step keeps taskId in the one save; handler waits (continue with short wait, max 3 tries) when no matching taskId yet; abort the task if the save fails; stale guard discards an orphan's result.
- Q2/Q3 Send webhook: NOT a built-in. It was only an example of a custom automation. Phase 5 builds the automation-step abstraction (public automation definitions users register); no webhook step ships. Tests use a test-only automation definition. Spec/roadmap "Send webhook built-in" wording is updated by the phase 5 docs task. Q2 (signing) and Q3 (response contract) are dropped.
- Q4 SEC-68: GraphQL triggerTask running private task definitions is a bug. Phase 5 fixes it in packages/background-tasks (own fix: commit; GraphQL triggerTask refuses private definitions as if unknown; internal TaskService triggers unaffected), plus the runner defences (stale guard, createdBy = requester, input never trusted).
- Q5 maxIterations: (a) one private runner task definition with a high ceiling; the handler enforces the automation definition's own maxIterations from the task's iterations and fails the step.
- Q6 secrets: no secret settings in workflow step config. Credentials (keys, tokens) belong to whoever writes the automation definition, in their own code/config (e.g. env), never set or seen by workflow editors. Phase 5 drops 'secret settings' (D67 secret part superseded); no encryption, no write-only marker, no secret stripping. Docs task updates spec/roadmap/decisions.
- Clarification: an automation step is code-defined by a developer (a 'webhook' automation is one such example, written by whoever needs it). The definition declares a zod schema for the info the workflow author passes in (e.g. URL); the workflow author adds the automation as a step and fills its config, validated against the zod schema at save and before run; the schema is exposed to the editor so the form renders it. Credentials stay in the definition's code/config.
- Q7 automation bypass: (a) save block only (BlockUpdateWhileInReview); move, folder-change, delete and trash blocks stay active for automations (R150 as narrowed).
