**Goal:** One CMS query, `listCmsEntryBlockingReviews(modelId: ID!, entryIds: [ID!]!)`, that answers "which of these entries have a review in progress that I may see". The admin calls it in 8b.7 (Task 19) before it starts the bulk trash background task for all loaded rows, so the 8a warning can be shown first (D164). The query returns the reviews of entries the viewer can read and nothing about the rest. In `packages/api-headless-cms-workflows` (wrapper use case, schema, query) and `packages/api-workflows` (the shared SDL type `WorkflowsBlockingReview`).

**Depends on:** nothing in 8b. It builds on the 8a.1 wrappers (`CurrentReviewViewer`, `CmsEntryAccess`, `toBlockingReview`) and is independent of 8b.1 and 8b.2. Task 4 of 8b.2 also edits `packages/api-workflows/src/graphql/WorkflowsSchemaFactory.ts` (the type `WorkflowsStepRunInfo`) and `workflowsSchema.test.ts`; the two tasks touch different hunks, so they apply in either order. 8b.4 (Tasks 8, 9) needs this SDL for its documents (the API need not run); 8b.7 (Task 19) needs the query.
