# Workflows Phase 8b.7: App glue

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Read first:** `../00-shared.md`: Global Constraints (and through them every Global Constraint of 8a), Rulings R253, R254, R260, R262, R265, R266 and the inherited R202, R204, R210, R220, R237, R238, R243, Assumptions A95, A96, Task order, Interfaces by task (Tasks 17-19 and the entries of the tasks they consume: Task 7, Task 8, Task 9, Task 10, Task 13). **Goal:** The thin, app-specific glue the shared work of 8b.4-8b.6 needs, in the CMS and Website Builder packages, plus the one shared change that only the CMS uses. The CMS and WB each subclass the shared `ReviewChangeMessageHandler` once and bind it to `WebsocketEventHandler` (R237), so `workflows.reviewChanged` frames reach the activity bus per app. Each editor gets a content reloader (CMS: over the undecorated form presenter; WB: evict the page from `FullPageCache`, read it again, apply it with `editor.updateDocument`) that the init params carry as `contentReloader` (R262). The shared `ActiveReviewGuard` gains `confirmBlocking`, `runBulk` is rebuilt on it, and the CMS bulk trash of all loaded rows asks `listBlockingReviews` by entry id, in chunks of 200, before it starts its background task and shows the 8a warning (R265).

**Depends on:** 8b.1-8b.6. Tasks 17 and 18 subclass Task 10's `ReviewChangeMessageHandler` and implement Task 13's `IReviewContentReloader` (the `contentReloader` init field and the notice live there); Task 19 needs Task 7 (the server query), Task 8 (`listBlockingReviews` on the use cases) and Task 9 (the CMS gateway method). Nothing later in 8b consumes this sub-phase except the docs of 8b.8.
