**Goal:** The background task of a workflow step run is kept until its review is deleted, and workflows can read it. The task stops cleaning itself up (Task 3), deleting a review cleans up the task of every attempt (Task 3), and the engine gets one internal use case `GetReviewStepRunUseCase` that returns only the status, times, run count, outcome and fixed reason of one attempt (Task 4). The Headless CMS and Website Builder wrappers expose it as the queries `getCmsEntryReviewStepRun` and `getWebsiteBuilderPageReviewStepRun`, for viewers with read access to the content and the workflows permission `editor` or `reassign` (Tasks 5 and 6). In `packages/api-workflows`, `packages/api-headless-cms-workflows` and `packages/api-website-builder-workflows`.

**Depends on:** nothing in 8b.1 or 8b.3 (the three API sub-phases are independent of each other). Task 3 is independent of Tasks 4-6; Task 4 -> Task 5 -> Task 6 (Task 5 and 6 import Task 4's exports from the built `@webiny/api-workflows`, so Task 4 builds that package before it commits). 8b.4 consumes the SDL of Tasks 5 and 6 for its GraphQL documents (the API need not run); 8b.5 consumes the query through the gateway.

## Review Focus for this sub-phase

Review Focus 1 (a run task leaks its raw error or input: Task 4 pins the exact `ReviewStepRunInfo` keys with `output.error`, `output.state` and `input` set, Tasks 5 and 6 pin it through the wrapper and GraphQL), 2 (the step run read opens arbitrary tasks: Task 4 pins `StepRunNotFound` for an unknown task id, another review's task id and an unknown step, with no task read; Tasks 5 and 6 pin the editor/reassign gate, the guard's read access, the other app's review as not found, and that a refused call never reaches the engine or the task) and 4 (run tasks pile up or a review delete fails because of a task: Task 3 pins every task id cleaned after the abort, null ids skipped, a throwing cleanup logged and the delete still succeeding, nothing cleaned for a review whose delete failed). Also: R87 (a task read that throws is a failed Result, never a rejection) in Tasks 4-6, and R46 (the other app's review is not found) in Tasks 5 and 6.

## Done when

All tasks reviewed clean, final review clean. `WorkflowStepRunTaskDefinition` has no `selfCleanup`; `DeleteTargetReviewsUseCase` cleans up every non-null task id of every step (earlier runs oldest first, then the current one) after the abort, and a cleanup that throws is logged with `reviewId` and `taskId` and never fails the delete. `GetReviewStepRunUseCase` returns `ReviewStepRunInfo | null` with exactly its seven fields, the status mapped from `TaskDataStatus` (`success` to `done`), the run count computed as the task handler does (floored at 0), outcome and reason from the review, times from the review with the task as fallback; an unknown task id, another review's task id and an unknown step are `Workflows/Review/StepRunNotFound` and the task is never read; a gone task is `null`; a task read that throws is `Workflows/Review/Persistence`. Both wrappers refuse viewers without `editor` or `reassign` and viewers without read access with `Workflows/NotAuthorized` (action "view a step run"), report the other app's review as not found, and reach neither the engine nor the task when refusing; both queries are in the SDL, the license tests and the registration tests. Each API test file passes with `yarn test` and `yarn test:os` (one at a time); `yarn check:test:types` is clean for `api-workflows`, `api-headless-cms-workflows`, `api-website-builder-workflows` and `ai-powerups`; every changed package builds with `--no-cache`.
