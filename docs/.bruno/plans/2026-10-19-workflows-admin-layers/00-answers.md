# Workflows admin layering refactor — user answers (2026-10-19)

Questions continue the 9c numbering (9c ended at Q68). All accepted as proposed ("ok").

- Q69 Per-app variation: use cases are one per operation and live once in app-workflows. Only the gateway varies per app: a routing gateway picks the CMS or Website Builder implementation from the review's or workflow's namespace (`cms.*`, `wb.page`). This removes runtime passing of use cases through `init()`/props and the Content Reviews list's per-row `useCases` binding. No per-app use-case tokens or subclasses.
- Q70 Presenters and services inject exactly the use cases they call through DI. Mounting components and the trash guards stop passing use-case bundles; `XReviewFeature` no longer resolves `useCases`.
- Q71 Layers: the gateway does the GraphQL call and throws `GraphQLOperationError` from one shared helper (replacing the 17 inline copies and `toOperationError`), keeping the null-is-a-value cases (`getTargetReview`, `getStepRun`), boolean `folderExists`, and passing transport errors through. The repository maps DTO <-> domain and owns caching. The use case is a thin `execute()` and is the decoration point.
- Q72 One repository and one gateway per area, no per-operation pass-through repositories: `ReviewRepository`, `WorkflowEditorRepository`, `WorkflowConfigRepository`, `WorkflowSettingsRepository`, each shared by its area's use cases. Gateways stay per area (per app for review and editor; shared for config and settings). App-specific details stay in each app's gateway (WB "Pages" row, CMS model-list reshape, namespace checks, WB `listBlockingReviews` empty list).
- Q73 The workflow-list cache moves into `ReviewRepository`; the store and delete workflow use cases clear it, so the editor presenter stops calling `invalidateWorkflows` by hand.
- Q74 Tests follow base admin: gateway tests with a fake GraphQL client; use-case tests with a fake gateway plus the real repository and cache; presenter tests with small per-test fakes of the injected use cases. The four aggregate fakes and their setup kits are replaced; behaviour assertions stay.
- Q75 Order: one sub-phase per area — settings, config, editor, review — then cleanup and docs.
- Q76 Naming and layout follow Website Builder `features/pages/deletePageRevision`: one folder per operation with `abstractions.ts`, `XUseCase.ts`, `feature.ts`; the area repository and gateway in their own folders; tokens scoped `Workflows/...`; no `Impl`/`Implementation`/`Abstraction` suffix on exports or files (alias only the abstraction as `XAbstraction`).
