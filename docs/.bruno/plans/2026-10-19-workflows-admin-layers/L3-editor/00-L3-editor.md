The CMS and Website Builder editor gateways register under one shared token, `WorkflowEditorAppGateway`, and the app-neutral routing gateway picks one by the editor's `app`; the envelope rules and the mapping exist once, in `app-workflows`. The editor presenter injects the six editor use cases; the per-app editor tokens and bundles are gone. In `packages/app-workflows`, `packages/app-headless-cms-workflows` and `packages/app-website-builder-workflows`. Users see no change.

## Review Focus for this sub-phase

- **Review Focus 1 (an error or a value changes):** `WorkflowEditorGateway.test.ts` pins the envelope conversion for all six operations (code, message and data kept; the fallback `The request failed.` with `code` and `data` `null`; the transport `Error` and a plain `Error` of an app gateway passed unchanged), `folderExists` answering `false` without an error and throwing for a non-boolean, and the conflict, rule-validation and blocked-delete data; the use-case tests pin the mapping (ported from `WorkflowEditorUseCases.test.ts`) and that the use case passes the gateway's error through.
- **Review Focus 3 (an operation reaches the wrong app):** the routing gateway picks by `app`, the first registered claimant wins and runs once (A114), an unregistered app throws `No workflows app is registered for "<app>".` and calls no gateway, and every app gateway receives exactly its old parameter object without `app` (`getWorkflow(id)`, `deleteWorkflow(id)`, `{ search, limit, after }`, `{ data, savedOn }`, `{ stepConfig, requesterId, folderId, modelId }`, `{ id, type }`). The presenter tests assert `app: "cms"` on every parameter assertion and `app: "wb"` for a WB editor.
- **Review Focus 6 (flag):** `[AW]/app.test.tsx` resolves the routing gateway, the repository (singletons) and the six use cases (transient) with the flag on and fails to with it off; `[CMS|WB]/index.test.tsx` find the app's gateway under the shared token only with the flag on.
- **Review Focus 7 (no duplication):** the CMS and WB editor gateways keep only their documents, variables and app specifics (the CMS list reshape, the WB Pages row, the ignored `modelId` and folder type); unwrapping, null rules and mapping exist once in `app-workflows`.
- **Review Focus 8 (a consumer gets a use case at runtime, or injects more than it calls):** the presenter's `dependencies` equal R352's final array; no `useCases` prop, init field or mounting-feature result is left for the editor (Task 6's greps).
- **Review Focus 10 (an app's gateway is missing from the routing gateway):** each app's index test resolves the routing gateway after the render with a stub of the other app registered as a factory (which proves the routing singleton was not built during the render) and routes its own app to the real gateway and the other app to the stub; `[WB]/index.test.tsx` renders `WorkflowsAdminApp`, `CmsWorkflows`, `WebsiteBuilderWorkflows` in that order and routes `cms` and `wb` to the two real gateways through `GetWorkflowUseCase`.
- **No behaviour change (R342):** no GraphQL document, variable or envelope handling changes; every assertion of the replaced tests is kept on the new path (the two `feature.test.ts` files run their behaviour cases through the shared use cases over the real app gateway).
