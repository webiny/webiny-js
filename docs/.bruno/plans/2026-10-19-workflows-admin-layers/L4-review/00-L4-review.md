> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The review area of `app-workflows` follows presenter -> use case -> `ReviewRepository` -> `ReviewGateway` -> per-app `ReviewAppGateway`. The CMS and Website Builder review gateways register under one shared token; the app-neutral `ReviewGateway` routes each call by the review's namespace or the list's app and unwraps the envelope once; `ReviewRepository` maps and caches the workflow list per app; seventeen use cases replace the review bundle's operations; then every consumer moves, group by group: target and request (and the cache invalidation moves from the editor to the store and delete use cases), details and action dialogs (with the row binding and the editor session), Content Reviews list and widgets, trash. After L4 no review use case travels through `init()`, props, a row binding or a session, and nothing outside the old bundles' own files and tests uses them (L5 deletes them). Users see no change.

**Depends on:** L1 Task 1 (`toOperationError` at `[AW]/gateway/`), L3 Tasks 5 and 6 (`WorkflowAppKind`; the editor routing gateway, repository and the six editor use cases, `StoreWorkflowUseCase` and `DeleteWorkflowUseCase` among them; the editor presenter on the editor use cases; the editor mounting features resolving `{ reviewUseCases, app }`; the CMS and WB index tests with the editor half of Review Focus 10). L5 Task 14 consumes everything here (it deletes the old bundles, their interfaces, the fakes, the per-app review tokens and the two bridges).
