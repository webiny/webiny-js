**Goal:** The editor's view, in `packages/app-workflows/src/editor/presentation/editor/components`: the shared `WorkflowEditorView` (resolves the editor presenter, initialises it with the per-app `useCases`, `reviewUseCases` and `app` adapter, mounts the step drawer) over the presentational `WorkflowEditorLayout`; the shell (model panel, sticky header, loading, load-error, no-permission and no-workflow states); the flow (Draft card, numbered step cards with drag, up, down, edit and delete, `+` connectors, Published card, the empty `No steps yet` box, scroll to a failing card); the step type picker (a card per type, disabled with its reason); the seven dialogs; the banners; and the leave guard (router guard plus `beforeunload`). The view reads only render-ready view models and calls presenter commands (R234); every text that interpolates a model, workflow or reviewer name is assembled by the presenters (Tasks 9, 10, 14), the view contains the fixed strings only.

**Depends on:** 9a.5 (Task 14: `StepDrawer`, which the view mounts), 9a.4 (Tasks 8, 9, 9b and 10: `WorkflowEditorPresenter`, its feature and view-model types, `WorkflowEditorAppAdapter`, `getStepTypeOptions`, `StepTypeId`; the presenter members the view calls), 9a.3 (Task 5: `IWorkflowEditorUseCases`). Tasks 20 and 21 (9a.7) mount `WorkflowEditorView` per app; Task 20 also adds `WorkflowEditorRoute` and `WorkflowEditorMenu`.

**The presenter surface the view uses.** Task 15's `WorkflowEditorViewPresenter` is a `Pick` of `WorkflowEditorPresenter.Interface` (Tasks 9, 9b and 10); the view-model types are the presenters' own (`ModelPanelVm`, `WorkflowHeaderVm`, `EmptyWorkflowVm`, `StepCardVm`, `WorkflowFlowVm`, `TypePickerVm`, `OptionsBannerVm`, `SaveBannerVm`, `WorkflowEditorDialogVm`, `DialogReviewVm`, `ScrollRequestVm`). `WorkflowEditorView` passes the real presenter to the layout, so a name mismatch is one type error on that line. **Drawer wiring (R284).** The editor presenter owns `openStep`, `closeStep`, `vm.openStepId` and `getNamespace` (Tasks 9, 9b); the view renders `<StepDrawer source={presenter} stepId={vm.openStepId} />` (`presentation/stepDrawer/StepDrawer.tsx`, Task 14). The drawer opens and closes its own presenter from `stepId` and calls `source.closeStep()` when it closes itself; the view holds no drawer logic.
