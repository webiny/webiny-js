## Review Focus for this sub-phase

Review Focus 2 (a rule loses data on edit, reorder or save: Task 9 round trip and Task 10 ids), Review Focus 1 (error vs warning kinds: Tasks 11 and 12), Review Focus 4 (saved references: labels per state in Task 11), Review Focus 5 (teams off: Task 12), Review Focus 6 and 7 (Test routing signature and prose against the server's answer: Task 13). Additional checks for this sub-phase:

1. **Lossless model:** `assignmentToConfig(readAssignment(x))` equals `x` as JSON (key order ignored) for every stored shape the server accepts and for the odd shapes of R314; no `null` is ever emitted for an absent condition; an unknown strategy and an unknown target type survive until the admin picks one.
2. **Pure functions:** no file in this sub-phase imports MobX, React, vitest (outside tests) or the DI container; every helper returns new arrays and objects and never mutates its input.
3. **One exported function per file**, one named import per line, no nested call arguments, no multi-line ternaries, `//` and `/* */` comments ending with a period.
4. **Existing behaviour:** the 9a tests of `getStepSummary`, `getStepWarnings`, `validateWorkflowDraft` and the editor presenter keep their meaning; only the People summary strings gain the strategy part (R308) and their expectations are updated in Task 12.
5. **Copy:** every string is copied into the task text from the contract, `00-answers.md` or `research-spec.md` sections 4 and 7; the three strings the contract fixes by fallback (copy gaps 10 and 11) are the ones the controller accepted.
