Also check:

- **The envelope contract holds for every new method** (R204): a server error is an envelope the gateway returns and the use case throws as a `GraphQLOperationError` that keeps `code` and `data` (a rule validation error keeps `ruleId` and `field`); a transport failure passes as it is; `folderExists` throws only for an error or `null`.
- **The shared use-case class stays plain** (R237): no `createImplementation` on `WorkflowEditorUseCases`; the existing per-app subclass test now also runs `inspectRouting` and `folderExists` through each subclass's own gateway.
- **`app-workflows` never imports `app-aco`** (R292): `buildAppFolders` takes plain nodes; only the CMS and WB packages import `@webiny/app-aco`, and both list it in `dependencies` (adio clean).
- **The documents are the schema's**: the WB root is `websiteBuilder`, the WB documents have no `modelId` and no folder type, the CMS documents send the bare `modelId` and the folder `type`.
- **Warnings 9b cannot compute stay out**: the fragments select no e-mail, no roles, no load numbers.
