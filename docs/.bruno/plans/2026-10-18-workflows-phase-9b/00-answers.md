# Phase 9b — user answers (2026-10-18)

Questions continue the 9a numbering (9a ended at Q48).

- Q49 Team membership for the rule target picker: extend the workflows `listUsers` (api-workflows `ListWorkflowUsersUseCase`), not base Webiny. It gains an optional `teamIds` filter and returns each user's team ids. Base Webiny has teams off by default (feature flag `advancedAccessControlLayer.teams`): with teams off, `listUsers` must not query teams and must not return team data. Base packages are not extended unless necessary, since everything else must work without workflows.
- Q50 Rule warnings needing data the editor lacks: 9b shows only the warnings it can compute (deleted user or team, user no longer in the reviewing teams, team target not a reviewing team, deleted or restricted folder). Read access ("{Name} can't read {Model} content.") and exclusions ("{Name} is unavailable (excluded until …)…", the picker's "Unavailable" note) are not shown in the editor; Test routing reports them through the server's skipped people.
- Q51 Server errors on a rule: the workflows API adds `ruleId` to the validation error data and names the rule field (`config.assignment.rules.target`); schema errors keep `config.assignment.rules.<index>.…`. Rule messages become rule-neutral ("The target user is not a member of the step's teams."), and the editor shows "Rule {n}: {message}" on the step card and marks the rule card and field.
- Q52 Team targets outside the step's teams: `StoreWorkflowUseCase` rejects them, with `ruleId` (Q51) and the message "The target team is not one of the step's reviewing teams.". The editor shows it as a rule error, and client validation blocks Save on it too.
- Q53 Stale rule targets block Save on the client: a user outside the reviewing teams, a team outside them and a deleted user are rule errors (text "{Name} is no longer in the reviewing teams.", "{Team} is not a reviewing team.", "The assigned user was deleted."), with the toast "Fix the highlighted steps before saving.". Deleted and restricted folders stay non-blocking warnings.
- Q54 Folder control: the shared searchable WorkflowPicker over folder paths, for the rule's "Content is in folder" and the Test routing "Folder" input. Each app supplies its folders through its editor adapter (CMS: ACO folders of type `cms:<modelId>`; WB: `wb:page`); app-workflows does not depend on app-aco. A saved id resolves to its path when listed; when not listed, `folderExists` true means "Restricted folder" and false means "Deleted folder".
- Q55 Test routing detail: the workflows API extends `inspectRouting`. The trace lists every rule (rules after the deciding one get outcome `notEvaluated`), a not-matched row names the failed conditions (requesterUser, requesterTeam, folder), and the result adds the narrowed team id and the first few candidate ids. The editor composes the design's sentences from that data.
- Q56 Scope: no `listStepCandidates` work in 9b (the roadmap line is stale) and the 8a `ReviewerPicker` stays as is. 9b touches only the editor; its docs task corrects the roadmap row and app.md.
- Q57 admin-ui: a first 9b task fixes `RadioGroup`, `CheckboxGroup` and `Checkbox` (observe items by reference, not deeply) in its own `fix(admin-ui)` commit and switches the 9a automation and AI tools forms back to them; 9b's new controls use them directly. This closes the 9a pre-merge gap.
- Q58 Teams off (`advancedAccessControlLayer.teams` disabled): `listStepTypes` reports the People step as unavailable with a reason (listed disabled in the editor, D122); `listTeams` returns an empty list without querying; `listUsers` skips team data (Q49). Saved People steps load read-only with a notice. Automation and AI steps keep working.
- Q59 Copy the design does not provide, accepted as proposed:
  1. Deleted team in a rule: "Deleted team" (muted, `group_off` icon) with the warning "The team was deleted."
  2. Test routing with no requester: the button stays disabled, hint "Choose a requester to test."
  3. Test routing rejected by validation: "Could not test routing: {server message}". The generic "Could not test routing: the server did not respond." stays for transport failures.
  4. Rule moved with the keyboard: "Rule moved to position {position} of {total}."
  5. Teams off: the People step's unavailable reason is "Teams are not enabled."; a saved People step shows "This step needs teams, which are not enabled. It can't be edited."
