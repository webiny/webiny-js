# @webiny/app-admin — Features, permissions and config

> Level 3 · commit 19c9ca1b91 · audited 2026-09-26

## Summary
This slice covers `packages/app-admin/src/features/*` (excluding `formModel`, audited separately), plus `src/permissions`, `src/config`, and `src/hooks`. It is mostly a large collection of small, single-purpose DI "feature" modules (abstraction + implementation + `feature.ts`, following the project's DI/feature convention closely and consistently), the schema-driven RBAC engine used by every `app-*` package, and the fluent `AdminConfig` API used to register menus/routes/theme. Code quality is generally high — small files, real rationale comments, and a permissions-engine unit test suite with good coverage of its core logic. Two real, confirmed bugs were found: a missing `await` that double-invokes the logout callback on every log-out, and a security finding tracked privately (SEC-16). Duplication is otherwise minor and mostly the same small patterns repeated 2-4 times (tenant/auth header-injection decorators, a fourth copy of admin-ui's already-triplicated `ListCache`, and a repeated menu-placement snippet).

## Public API
- `features/security/*`: `AuthenticationContext`, `LogInUseCase`, `LogOutUseCase`, `IdentityContext` — core session/auth state, registered at app bootstrap (`base/Admin.tsx`) and consumed throughout `presentation/*` (dozens of call sites, outside this slice).
- `features/tenancy`: `TenantContext`, `GraphQLClientDecorator`, `ApiStreamClientDecorator` — tenant header injection for all API calls; `TenantContext.setTenant` is called from the tenant switcher and `base/Base/UserMenu/ExitTenant.tsx`.
- `features/wcp`: `WcpService`/`ReactLicense` — license/feature gating; `ReactLicense` is the delegating wrapper around `@webiny/wcp`'s `ILicense` already noted in the level-0 `wcp` report.
- `features/webinySdk`: `WebinySdk` — authenticated SDK singleton; consumed directly (not via GraphQL) by ~9 files in `@webiny/app-file-manager` (file gateways/uploader) and ~9 files in `@webiny/webhooks`'s admin gateways.
- `features/listCache`: `ListCache<T>` — generic observable list cache, consumed by `accessManagement`'s `apiKeys`/`roles`/`teams` list use-cases.
- `features/adminAssistant`, `features/notifications`, `features/confirmation`, `features/tools`, `features/featureFlags`, `features/dateFormatter`/`stringFormatter`/`slugify`, `features/telemetry`, `features/newsletter`, `features/clipboard`, `features/buildParams`, `features/fileUrlFormatter`: small single-concern DI features, each with 1-10 consumers within `app-admin`'s `presentation/`.
- `permissions/`: `createPermissionSchema`, `createPermissionsAbstraction`/`createPermissionsFeature`, `usePermissionForm`, `PermissionRenderer`, `createHasPermission` — the schema-driven RBAC engine used by essentially every `app-*` package to gate CRUD UI (full-access/rwd/publish-unpublish/own-scope semantics).
- `config/`: `createAdminConfig`, `AdminConfig.*` (`Menu`, `Theme`, `LexicalTheme`, `Route`, `Dialog`, `Drawer`, `FieldRenderer`, etc.) — the fluent config API every `app-*` package's config plugin uses to register menus, routes and theme via `@webiny/react-properties`.
- `hooks/`: `useHotkeys`, `useKeyHandler`, `useDialog`/`useDrawer`, `useConfirmationDialog`, `useSnackbar`, `useModKey`/`useShiftKey`, etc. — shared React hooks used throughout `presentation/` and re-exported for other `app-*` packages.

## Bugs
| # | Severity | Location (file:line) | Problem | Failure scenario | Confidence |
|---|---|---|---|---|---|
| 1 | medium | `packages/app-admin/src/features/security/LogOut/LogOutUseCase.ts:11-18` | `LogOutUseCaseImpl.execute()` captures `const logoutCallback = this.authContext.getLogoutCallback()`, then calls `this.authContext.clear()` **without `await`**, and immediately afterwards does `await logoutCallback()`. But `AuthenticationContext.clear()` (`AuthenticationContext.ts:10-14`) itself does `await this.logoutCallback()` internally before resetting state. Since the two calls reference the same callback, it runs twice, and because `clear()` isn't awaited, the two invocations race instead of running in sequence. | Every provider's `logoutCallback` (e.g. `packages/cognito/src/admin/presentation/Cognito/CognitoPresenter.ts:396-403`, which calls `signOut()` and resets local auth state) fires twice per log-out, with the two calls overlapping in time rather than one completing before the next starts. This can produce a redundant sign-out/redirect call and duplicate local state resets on every log-out. | high |
| 2 | medium | `packages/app-admin/src/features/webinySdk/WebinySdk.ts` | Security finding SEC-16 — see private notes. | — | high |

## Duplication
- `features/listCache/ListCache.ts` is app-admin's own reimplementation of the generic `ListCache<T>` pattern that the level-2 `admin-ui` audit already found triplicated verbatim across `AutoComplete/domains/ListCache.ts`, `MultiAutoComplete/domains/ListCache.ts`, and `IconPicker/domains/ListCache.ts`. This copy has the same public shape (`count`/`clear`/`hasItems`/`getItems`/`getItem`/`addItems`/`updateItems`/`removeItems`) plus a `keyField`-based `unionBy` dedup and a `setItems` method, and is consumed by `accessManagement`'s `apiKeys`/`roles`/`teams` `list*` use-cases (`features/accessManagement/{apiKeys,roles,teams}/list*/abstractions.ts`, `feature.ts`) — a fourth copy of the same small utility instead of one shared module.
- `features/tenancy/ApiStreamClientDecorator.ts:8-24` duplicates `features/tenancy/GraphQLClientDecorator.ts:4-22` almost line for line (both attach an `x-tenant` header sourced from `TenantContext.getCurrentTenant()`); jscpd confirms a 13-line clone. The same shape repeats for auth headers in `features/security/AuthenticationContext/ApiStreamClientDecorator.ts` vs `GraphQLClientDecorator.ts` (attach `Authorization`/`x-webiny-authorization` unless already present) — jscpd doesn't flag this pair (different header names/values break its structural match) but the control flow is identical.
- `features/tenancy/types.ts:1-4` re-declares the exact `Tenant` interface already defined in `features/tenancy/abstractions.ts:3-6`. Only the `types.ts` copy is exported publicly (`packages/app-admin/src/index.ts:57`); the `abstractions.ts` copy has no consumers (see Dead code).
- `config/AdminConfig/Menu.tsx:42-50`, `Menu/SupportMenu.tsx:21-29`, and `Menu/UserMenu.tsx:33-41` each repeat the identical "compute `placeBefore`/`placeAfter` from `before`/`after`/`pin`" block verbatim. jscpd confirms this: `Menu.tsx:39-64` ↔ `SupportMenu.tsx:18-54` (26 lines) and `Menu.tsx:68-77` ↔ `UserMenu.tsx:53-62` (10 lines).
- `config/AdminConfig/LexicalTheme/Color.tsx` and `Typography.tsx` share two ~11-13 line clones per jscpd (`Color.tsx:16-26`/`24-36` ↔ `Typography.tsx:30-39`/`39-55`); not read in full for this report, flagged from the jscpd data alone.
- `permissions/createPermissions.ts`: `SchemaPermissions`'s `canCreate`/`canEdit`/`canDelete`/`canPublish`/`canUnpublish`/`canAction` methods (lines ~100-200) all repeat the same "if full access, return true; look up the entity; get permissions; if none, return false; `permissions.some(...)`" boilerplate, differing only in the final predicate — jscpd flags six pairwise clones within the file (lines 83-198).
- `hooks/useModKey.ts:4-33` and `hooks/useShiftKey.ts:8-48` duplicate the same "track a modifier key via `keydown`/`keyup` listeners into local state" pattern (jscpd: `useModKey.ts:21-33` ↔ `useShiftKey.ts:35-47`).
- `config/table/Column.tsx` has an 8-line self-clone (58-71 vs 67-72 per jscpd), and `config/table/index.ts:1-13` duplicates `presentation/trashBin/configs/Browser/Table/index.ts:1-14` (outside this slice, noted for completeness only).

## Dead code
- `features/tenancy/abstractions.ts:3-6` exports a `Tenant` interface with no consumers anywhere in the codebase (codegraph/grep: the only usage found is the separate, duplicate declaration in `types.ts`, which is what's actually re-exported from `index.ts`). There is no barrel file in `features/tenancy` re-exporting it either, so it is unreachable beyond its own file.

## Convention issues
- `features/tenancy` violates the "one abstraction/type per file" convention by declaring the same `Tenant` shape in both `abstractions.ts` and `types.ts` — a single definition (in `types.ts`, since that's the one actually consumed publicly) would remove the dead duplicate.
- The `Menu`/`SupportMenu`/`UserMenu` pin-placement logic (see Duplication) should be a shared helper rather than copy-pasted per component — the DI/feature files elsewhere in this slice are otherwise consistently one-concern-per-file, so this stands out.
- Everything else in this slice (DI naming, `Impl` suffix, abstraction/implementation split, namespace-scoped `.Interface` types, minimal barrel exports) follows the project's conventions closely; no other meaningful violations found.

## Test gaps
- No test coverage for `LogOutUseCase`/`AuthenticationContext.clear()` — this is exactly what would have caught Bug #1 (double logout-callback invocation).
- No test coverage found for `WebinySdk`'s tenant binding (Bug #2) — a test asserting the SDK reflects a `TenantContext.setTenant()` call after construction would have caught it.
- Aside from `permissions/createPermissions.test.ts` (solid coverage: full-access, entity-level access, rwd actions, publish/unpublish, and own-scope semantics), no `__tests__` were found anywhere else in this slice — `features/tenancy`, `features/security`, `features/wcp`, `features/webinySdk`, `features/adminAssistant`, `config/*`, and `hooks/*` all have zero automated tests despite several of them (auth, tenancy, licensing) being exactly the kind of cross-cutting logic where a regression is easy to miss and expensive to hit in production.

## Recommendations
1. Fix `LogOutUseCase.execute()` (`features/security/LogOut/LogOutUseCase.ts:11-18`): `await this.authContext.clear()` and stop invoking `logoutCallback` a second time directly, since `clear()` already runs it — this executes on every user log-out.
2. Fix the tenant-isolation issue in `features/webinySdk/WebinySdk.ts` (full details in `docs/.reports/security.md`) so the SDK's tenant scope follows `TenantContext` live, the same way its `token` callback and the GraphQL/stream client decorators already do.
3. Consolidate the recurring small duplications: extract `ListCache<T>` (this package's copy plus admin-ui's three) into one shared module; factor the tenant/auth header-injection decorators' shared shape into a single helper; extract the `Menu`/`SupportMenu`/`UserMenu` pin-placement computation into one function in `config/AdminConfig`.
