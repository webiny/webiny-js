# @webiny/app-admin — Components, base and infrastructure

> Level 3 · commit 19c9ca1b91 · audited 2026-09-26

## Summary
This slice covers `packages/app-admin/src/{components,base,domain,modules,errors,exports}` plus the top-level `index.ts`/`routes.ts`/`types.ts` — the package's component library (22 component folders, e.g. Table, IconPicker, LexicalEditor, BulkActions, Permissions, Dialogs/Drawers, OverlayLayout), the app-shell wiring (`base/Admin.tsx`, `base/Base.tsx`, DI providers), the `Identity` domain model, the `AccessManagementExtension` module, network-error UI, and the `exports/admin/*` sub-path barrels consumed by downstream apps. The code follows the package's MobX Presenter + Repository/Gateway DI pattern consistently and is generally sound, but test coverage in this slice is very thin, there are two duplicate/dead-weight app-shell providers mounted simultaneously, and the ~30 form `FieldRenderers` are heavily copy-pasted per field type rather than parameterized.

## Public API
- `components/index.ts` barrel (re-exported from the package's own `index.ts`) — `AdminLayout`, `DialogsProvider`, `OptionsMenu`/`OptionsMenuItem`/`OptionsMenuLink`, `Filters`, `BulkActionButton`/`useBulkActionDialog`, `OverlayLayout`, `EmptyView`, `SimpleForm*`, `SingleImageUpload`, `LexicalEditor`, `IconPicker`, `SplitView`, `Permissions`, `SearchUI`, `RegisterFeature`, `RolesMultiAutocomplete`, `TeamAutocomplete`, `TeamsMultiAutocomplete`, `DeveloperMode`, `ListView`, `Table` — consumed throughout app-admin's own `presentation/` layer and re-used directly by `app-headless-cms`/`app-website-builder` (e.g. `Table`, `Permissions`, `ConfirmationDialog`, `IconPicker`).
- `exports/admin/*.ts` — the `webiny/admin/*` sub-path exports: `ui.ts` (dialog hooks, `AdminLayout`, `OptionsMenu`), `form.ts` (new `FormView`/`FieldBuilder` plus legacy `@webiny/form` re-exports), `security.ts` (permission helpers, login/logout use cases, `HasPermissionComponent`), `tenancy.ts`, `configs.ts` (`AdminConfig`), `ui/file-manager.ts`, `ui/lexical.ts`. These are the package's documented extension points for project code.
- `Admin` (`base/Admin.tsx`) — root composition component that registers ~10 DI features and mounts the app's provider stack; every app-admin-based application renders this once at the root.
- `Identity` (`domain/Identity.ts`) — MobX-observable identity/permission/role/team model with pattern-matched (`minimatch`) permission lookup; consumed by the security presentation layer package-wide.
- `SECURITY_PERMISSIONS_SCHEMA` (`domain/securityPermissionsSchema.ts`) and `AccessManagementExtension` (`modules/AccessManagementExtension.tsx`) — the reference implementation other "…Extension" feature modules in the app follow (register DI features, then declare routes/menus/breadcrumbs under `AdminConfig`).
- `ErrorOverlayNetworkErrorHandler` / `TenantIsDisabled` (`errors/`) — DI-registered `NetworkErrorEventHandler` implementation that shows the timeout/tenant-disabled/GraphQL error overlays.

Cross-package reimplementation: `components/SimpleUI/InputField.tsx` hand-rolls an `<input>` with Emotion CSS, a label, and error/description text — the same label+input+error+description composition `@webiny/admin-ui`'s `Input`/`FormComponent` primitives already provide (per admin-ui's own level-2 audit). It has no current consumers (see Dead code), so today the duplication is dormant, but it's a trap for anyone who rediscovers it instead of reaching for `@webiny/admin-ui`.

## Dead code
- `components/SimpleUI/InputField.tsx` — default-exported `InputField`; grep across the whole monorepo finds no reference outside its own file. Also reimplements `@webiny/admin-ui`'s `Input` (see Duplication).
- `components/NotAuthorizedError/NotAuthorizedError.tsx` (and its `SecureRouteError.svg`) — exported from its local `index.ts`, but grep shows zero consumers anywhere in the repo, including app-admin's own `SecureRoute`/`HasPermission` components.
- `components/BulkActions/Worker.ts:17` — `IWorkerActions<T>` interface is exported but never imported anywhere else in the repo (grep: no matches outside its declaration), and its method signatures (`process(callback)`, `processInSeries(callback, chunkSize?)`) no longer match the actual `Worker<T>` class (`process(items, callback)`, `processInSeries(items, callback, chunkSize)`), so it would mislead if ever picked up.

## Convention issues
- `components/ConfirmationDialog` is not re-exported from `components/index.ts` or any `exports/admin/*.ts` barrel, yet `app-headless-cms` (`src/admin/components/Dialogs/{Delete,Publish,Trash,Unpublish}*ConfirmDialog.tsx`) imports it via a deep relative path straight into `packages/app-admin/src/components/ConfirmationDialog` — an undocumented cross-package dependency on an internal path instead of a maintained public export.
- `components/SimpleUI/InputField.tsx` is the only default-exported component (`export default React.memo(InputField)`) found in this slice; every other component uses named exports, per the convention used consistently elsewhere in the package.

## Test gaps
Of the roughly 230 files in this slice, only four test files exist, and all of them test presenters: `components/IconPicker/{IconPickerPresenter,IconRepository}.test.ts` and `components/Table/components/Table/{ColumnVisibility/ColumnsVisibilityPresenter,Columns/ColumnsPresenter}.test.ts`. Everything else has no automated coverage: all ~30 `FieldRenderers` and the `ObjectRenderer`/`DynamicZone`/`MultiValueDynamicZone` machinery, `OverlayLayout`, the `Dialogs`/`Drawers` context providers, `BulkActions` (`BulkActionRunner`/`Worker`), `Permissions`, the `LexicalEditor` wrapper, `AdminLayout`, and `base/Admin.tsx`'s entire provider/DI wiring. The one existing `ColumnsVisibilityPresenter` suite only exercises `ColumnsVisibilityUpdater.update` with a function-style updater, not a plain-value updater, so it does not catch Bugs #1.

## Recommendations
1. Fix the plain-value branch in `ColumnsVisibilityUpdater.update` (`components/Table/components/Table/ColumnVisibility/ColumnsVisibilityUpdater.ts`) so a directly-passed visibility object is actually applied instead of silently discarded, and add a test for that branch.
2. Delete one of the two identical `UiStateProvider`/`AdminUiStateProvider` files and remove the corresponding entry from `base/Admin.tsx`'s `providers` array; separately, consider consolidating the ~15 near-identical `FieldRenderers` (text/textarea/number × single/multi) behind one parameterized renderer, since they account for the bulk of this slice's internal duplication.
3. Remove the confirmed-dead `components/SimpleUI/InputField.tsx`, `components/NotAuthorizedError`, and `IWorkerActions`, and add presenter/behavior tests for the untested `BulkActions`, `Dialogs`/`Drawers`, and `ObjectRenderer` code before it grows further.
