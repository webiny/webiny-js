# @webiny/app-admin — Presentation

> Level 3 · commit 19c9ca1b91 · audited 2026-09-26

## Summary
This slice (`packages/app-admin/src/presentation`, ~8.2k lines) holds `app-admin`'s MVP-style presentation layer: MobX presenters and their data sources for access management (roles/teams/API keys, each with its own list, form and autocomplete presenter), the generic reusable `ListPresenter`/`SelectionController`/`QueryMatcher`/data-source trio that most list-backed features build on, the trash bin feature (presenter, data source, table/cell components), the command palette, drag-and-drop `SortablePresenter`, the installation/system-installer wizard, and a handful of small context hooks (`useIdentity`, `useTenantContext`, `useWcp`, `useFeatureFlags`, `useBuildParams`). Health is good: the generic `ListPresenter`/`QueryMatcher`/`SelectionController` core is careful, well-commented and has a dedicated test file, and — notably — none of the six `mobx.autorun`/`reaction` call sites in this slice repeat the unbounded-leak pattern flagged in `@webiny/app`'s `useRoute` (level 2); every one of them disposes the autorun via the `useEffect` cleanup return value. The main issues are structural duplication (the Roles/Teams/ApiKeys access-management trio is a near-identical three-way copy-paste) and one leftover debug `console.log` in the installer's error path.

## Public API
This slice is internal to `app-admin` (re-exported through the package's `~/index.js`/`~/exports/admin.js` barrels for use elsewhere in the package and by extensions), not a separate npm package, so "consumers" below are other `app-admin` modules/extensions rather than other workspace packages.
- `ListPresenter` (`listPresenter/abstractions.js` + `ListPresenter.ts`) — the generic list state machine (search/sort/filter/selection/pagination); consumed by `TrashBinPresenter`, `RolesPresenter`, `TeamsPresenter`, `ApiKeysPresenter`, and `rolesAutocomplete`/`teamsAutocomplete` presenters.
- `TrashBinPresenter`/`TrashBinProvider`/`useTrashBinPresenter` (`trashBin/*`) — used by `app-admin`'s trash-bin browser config and re-exported for `app-headless-cms`/`app-file-manager`-style trash bin integrations (confirmed via a codegraph-equivalent grep: consumed by `app-admin/src/config` and other extensions).
- `SortablePresenter` (`sortable/*`) — generic drag-reorder presenter wrapping `@atlaskit/pragmatic-drag-and-drop`.
- `CommandPalettePresenter`/`Command` abstraction (`commandPalette/*`) — backs the cmd-K command palette; ships four built-in commands (`AskAiCommand`, `SendMessageCommand` — explicitly a removable demo, `CopyCurrentUrlCommand`, `SignOutCommand`).
- `useIdentity`, `useTenantContext`, `useWcp`, `useFeatureFlags`, `useBuildParams` — thin hooks wrapping DI-resolved services (`IdentityContextFeature`, `TenancyFeature`, `WcpFeature`, `FeatureFlagsFeature`, `BuildParamsFeature`) with MobX `autorun` sync into React state.
- `BrowserFilePickerPresenter`/`BrowserFilePicker` — confirmed consumed outside this slice by `app-file-manager`'s `FileManagerView`.
- `CustomIconsPresenter` (iconPicker) and `RolesAutocompletePresenter`/`TeamsAutocompletePresenter` — confirmed consumed by `app-admin`'s `IconPicker` custom-icons plugin and `RolesMultiAutocomplete`/`AccessManagementExtension` respectively.

## Duplication
- `accessManagement/roles/components/RolesView.tsx`, `accessManagement/teams/components/TeamsView.tsx`, and `accessManagement/apiKeys/components/ApiKeysView.tsx` are jscpd-flagged as near-identical across dozens of line ranges each (e.g. `RolesView.tsx:1-28` / `39-216` mirror `TeamsView.tsx:1-28`/`37-214` almost verbatim, and `ApiKeysView.tsx` mirrors large chunks of `TeamsView.tsx` too). The three presenters (`RolesPresenter.ts`, `TeamsPresenter.ts`, `ApiKeysPresenter.ts`) share the same structural skeleton (constructor DI wiring, `vm` getter, CRUD actions) with only entity-specific field names differing — this is a three-way copy-pasted feature rather than a shared base class/hook.
- `ApiKeysPresenter.ts` duplicates a block of ~9 lines within the same file: the `form.setData({...})` call built from a freshly-fetched/created `ApiKey` appears almost identically at lines ~96-102 (`selectApiKey`) and ~155-160 (`save`'s create branch) — the `save` copy is missing the `token` field that `selectApiKey`'s copy sets, which is likely intentional (a newly created key's token may not yet be returned the same way) but the near-identical blocks should be a shared private helper to avoid the two drifting further.
- `listPresenter/FolderAwareDataSource.ts` and `listPresenter/SimpleDataSource.ts` share ~13-24 line blocks (query/loadMore/buildWhere-style logic), and `SimpleDataSource.ts`/`FolderAwareDataSource.ts` both duplicate ~10-18 lines against `trashBin/TrashBinDataSource.ts` (the `query`/`loadMore` try/finally/`runInAction` scaffolding is copy-pasted three times instead of factored into a shared base class, even though all three already implement the same `IDataSource` interface).
- `trashBin/components/BulkActions/DeleteItems.tsx` and `RestoreItems.tsx`, and `trashBin/configs/Browser/BulkAction.tsx`/`EntryAction.tsx`, are smaller (7-11 line) jscpd-flagged clones of each other — same shape, different action verb.
- `sortable/SortablePresenter.ts:146-164` — the `onDragEnter` and `onDrag` handlers inside `registerDropTarget` are byte-identical (both just set `overIndex`/`closestEdge` from the drop-target self data); they could be merged into one handler reference.
- Per the `admin-ui` (level 2, `pickers.md`) audit, this slice's `listPresenter`/data-source family is a distinct, independently-duplicated pattern from admin-ui's `ListCache<T>` — no cross-package reimplementation, just parallel copy-paste within `app-admin` itself.

## Dead code
None found. Spot-checked the exports most likely to be unused (`BrowserFilePicker`, `CustomIconsPresenter`, `RolesAutocompletePresenter`) and all three have confirmed external consumers elsewhere in `app-admin`/`app-file-manager` (`FileManagerView.tsx`, `IconPicker/plugins/customPlugin.tsx`, `RolesMultiAutocomplete/index.tsx`, `AccessManagementExtension.js`). `SendMessageCommand` is unused functionally but is explicitly documented in its own file as a kept-on-purpose demo of the palette's `detailView` capability, not dead code.

## Convention issues
No meaningful violations found. The DI abstraction/implementation split, the `feature.ts`/`abstractions.ts`/`index.ts` file layout, and namespace-typed exports (`TrashBinPresenter.Interface`, etc.) are applied consistently across every folder in this slice, matching the pattern already established at lower dependency levels (`@webiny/feature`, `@webiny/app`). The per-domain `abstractions.ts` files (e.g. `trashBin/abstractions.ts`) group several closely-related gateway/presenter abstractions in one file rather than one-per-file, but this mirrors the same grouping convention used throughout the rest of the codebase for feature-scoped abstraction sets, so it is not flagged as a deviation.

## Test gaps
Only `listPresenter/ListPresenter.test.ts` exists in this entire slice — the generic, most-reused piece (`ListPresenter`) is tested, but none of its consumers are: `RolesPresenter`, `TeamsPresenter`, `ApiKeysPresenter` (the CRUD form/save/delete logic, including the `isUpdate` branching in `ApiKeysPresenter.save()` keyed off `createdOn`), `TrashBinPresenter`/`TrashBinDataSource` (restore/delete/bulk actions), `SortablePresenter` (drag/drop index-and-edge math in `computeDestination`/`getVisibleEdge`), `CommandPalettePresenter` (mode switching between AI mode and detail-view commands), and `SystemInstallerPresenter` (wizard step progression, install error handling) all have zero automated coverage despite containing the slice's real business logic and branching.

## Recommendations
1. Extract a shared base (or a small composition helper) for the Roles/Teams/ApiKeys presenter+view trio — the jscpd data shows dozens of near-identical line ranges across all three feature areas; a shared `AccessManagementListPresenter`/`AccessManagementListView` would remove most of the ~38 presentation-slice clones and prevent the three copies from silently drifting (as already happened with the `token` field between `ApiKeysPresenter`'s two `form.setData` blocks).
2. Add presenter-level unit tests for `TrashBinPresenter`, `SortablePresenter`, and `CommandPalettePresenter` — these hold non-trivial branching logic (bulk action fallback `where` clauses, drag destination-index math, AI-mode vs. detail-view command dispatch) with no coverage at all, unlike the well-tested `ListPresenter` they build on.
3. Factor the repeated `query`/`loadMore` try/finally/`runInAction` scaffolding out of `SimpleDataSource`, `FolderAwareDataSource`, and `TrashBinDataSource` into a shared abstract base (they already share the `IDataSource` interface), and remove the stray `console.log` in `SystemInstallerPresenter.installSystem`'s catch block.
