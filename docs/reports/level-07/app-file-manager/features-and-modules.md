# @webiny/app-file-manager — Features, modules and other presentation

> Level 7 · commit 19c9ca1b91 · audited 2026-09-26

## Summary
This slice covers everything in `packages/app-file-manager/src` except `presentation/FileList` and `presentation/FileDetails`: the DI feature layer (`fileUploader`, `settings`, `updateFile`, `deleteFile`, `listFiles`, `tags`, `getFile`, `permissions`, `resolveImageTool`, `fileModel`, `shared`), the `modules/` composition layer (including the AI re-enrichment streaming feature and the HeadlessCMS Asset/File field-type integration), `presentation/config` (the react-properties config-component tree), `presentation/FileManager` (the top-level view, drop-zone/paste handling and settings-aware upload gate), `presentation/Settings`, `presentation/fieldRenderers`, `presentation/hooks`, and the top-level `app.tsx`/`index.tsx`/`routes.ts`. Architecturally this is a clean, consistent Gateway → Repository → UseCase DI codebase that correctly reuses `@webiny/app-admin`'s `ListCache` (via a thin `FilesListCache` re-export, no reimplementation) and `@webiny/sdk`'s `Result`/`createFile`/`createFiles` upload primitives rather than rebuilding them. The real problems are concentrated exactly where the audit brief expected: the upload feature has a batch-cancel bug and a same-filename result-misattribution bug, the client-side paste-to-upload path silently skips the file-type/size validation that the drag-and-drop path enforces, the settings form has no numeric validation on the two file-size fields it saves via `parseFloat`, and `DeleteFileRepository` invalidates the cache without checking whether the delete actually succeeded.

## Public API
- `FileManager` (`app.tsx`) — the composition root that registers every feature/module for the package; mounted once by `packages/webiny`'s admin app wiring (not re-audited here).
- `FileUploader` (`features/fileUploader`), `UpdateFileUseCase`/`DeleteFileUseCase`/`ListFilesUseCase`/`GetSettingsUseCase` (`features/*`) — DI abstractions consumed by `presentation/FileList`/`presentation/FileDetails` (the sibling slice) and by `presentation/FileManager`.
- `useFile`, `useMoveFileToFolder`, `FileManagerViewConfig`/`useFileManagerConfig` (`index.tsx`) — the package's only top-level barrel exports; per codegraph, `useFile`/`useMoveFileToFolder` are consumed by a handful of files in `app-website-builder` and `app-aco` that need to resolve/move a file outside the File Manager UI itself.
- `CmsFilePickerRenderer`/`CmsMultiFilePickerRenderer`/`CmsAssetPickerRenderer`/`CmsMultiAssetPickerRenderer` (`presentation/fieldRenderers`) — registered as `AdminConfig.Form.FieldRenderer`s in `app.tsx`; consumed by `app-headless-cms`'s content-entry forms wherever a `file`/`asset` field type is used.

## Duplication
Package-wide jscpd summary: 42 clone pairs / 625 duplicated lines across `packages/app-file-manager/src`. Grouped by pattern (counts below are clone-pair counts, not lines):
- **Feature-layer test fixture/mock duplication (13 clones)** — in this slice: `features/{fileUploader,updateFile,deleteFile,listFiles,settings,tags}/*.test.ts` repeat near-identical DI container bootstrap / mock-gateway setup blocks (e.g. `FileUploader.test.ts` vs `UpdateFile.test.ts`, `DeleteFile.test.ts` vs `UpdateFile.test.ts`, `GetSettings.test.ts` vs `ListTags.test.ts`, plus several purely-internal repeats inside `FileUploader.test.ts` itself). Legitimate candidate for a shared test-harness helper (e.g. a `createTestContainer(mocks)` factory), not urgent.
- **`presentation/FileList`/`presentation/FileDetails` test duplication (20 clones, largest 65 and 60 lines)** — `FileGrid.test.ts`/`FileTable.test.ts`, `FileListPresenter.test.ts`/`FileDetailsPresenter.test.ts`, and `GraphQLInputMapper.test.ts` account for the bulk of the package's duplicated lines. This is outside this slice's folders; see the sibling `presentation/FileList`+`presentation/FileDetails` slice report for detail.
- **Config-component (react-properties) registration boilerplate (5 clones)** — `presentation/config/configComponents/Browser/{Grid,Table}/Thumbnail.tsx` and `presentation/config/configComponents/FileDetails/Thumbnail.tsx` (`packages/app-file-manager/src/presentation/config/configComponents/*/Thumbnail.tsx`) are the same 16-line `makeDecoratable` + nested `<Property>` wrapper 3 times over, differing only in the property-tree names; `FileDetails/Action.tsx` and `Browser/Grid/Action.tsx` share a near-identical 21-line block, and `Browser/BulkAction.tsx`/`Browser/Filter.tsx` share a 9-line block. A small `createThumbnailConfigComponent(scopeIds, propertyName)` / `createActionConfigComponent(...)` factory would remove this.
- **Hook duplication (1 clone)** — `presentation/hooks/useCmsImageEditor.ts:61-73` and `presentation/hooks/useEditImage.ts:38-51` share the same "map file metadata ↔ `ImageEditorValue`, call `UpdateFileUseCase`, snackbar on success/failure" logic.
- **Src-level self-duplication in `FileUploader.ts` (2 clones)** — the per-job progress-patch block (`this.jobs[idx] = { ...this.jobs[idx], progress: {...} }`) is repeated near-verbatim inside `upload()` (lines 109-115) and twice inside `uploadMany()` (lines 205-214, 228-235); a small private `patchJob(jobId, patch)` helper would collapse all three.
- **`app.tsx` self-duplication (1 clone)** — see Bug #6; the `<RegisterFeature feature={GetFileFeature} />` line is duplicated verbatim.

No reimplementation of lower-level utilities was found: `FilesListCache` is a straight re-export of `@webiny/app-admin`'s `ListCache` (not a fourth copy of the `ListCache<T>` pattern flagged in `admin-ui`/`app-admin`), and the upload/list/delete gateways all delegate to `@webiny/sdk`'s `Result`-returning methods rather than re-implementing GraphQL error unwrapping.

## Dead code
- `FileUploader.abort(jobId)` (`features/fileUploader/FileUploader.ts:269-275`, part of the public `Abstraction.Interface`) — codegraph: no consumers, and a repo-wide grep for `.abort(` calls into this feature found none either; the only per-job cancel affordance is exposed but nothing in `presentation/FileManager` or the sibling `presentation/FileList` slice currently calls it. This also means Bug #1 above is latent rather than actively user-facing today.
- No other unused exports were found in this slice; `modules/`'s smaller components (`ReenrichWithAi.tsx`, `StreamingPlaceholder.tsx`, the `HeadlessCms/fieldType` renderers) are all wired up through `app.tsx`'s `AdminConfig.Form.FieldRenderer` registrations or a `feature.ts`.

## Convention issues
- `features/settings/abstractions.ts` bundles `GetSettingsRepository.save()` onto the "get" repository/abstraction, with no corresponding `SaveSettingsUseCase` abstraction — every other feature in this slice (`updateFile`, `deleteFile`, `listFiles`, `tags`) follows a strict one-operation-per-abstraction-set Gateway→Repository→UseCase triad; settings save breaks that symmetry by piggy-backing on the get-side objects instead of getting its own UseCase.
- Otherwise the slice follows AGENTS.md's DI-naming/one-abstraction-per-file/interface-export conventions consistently (interface `IXxx` + abstraction `Xxx` + implementation `XxxImpl`, one per file), and `index.tsx`'s top-level barrel is minimal (only `useFile`, `useMoveFileToFolder`, `FileManagerViewConfig`), matching the "minimal barrel exports" convention.

## Test gaps
- `features/fileUploader/FileUploader.test.ts` has 14 tests covering single/batch upload, progress, cache updates and partial-failure handling, but none exercise `abort(jobId)`, and none use two files with the same name in a batch — both gaps line up exactly with Bugs #1 and #2.
- `features/deleteFile/DeleteFile.test.ts` was not checked against a "gateway returns `false`" scenario; there is no test asserting the cache is left untouched when delete "succeeds" with a falsy result (Bug #3).
- `features/settings/GetSettings.test.ts` only covers the get path; there is no test for `save()`/`SaveSettingsGateway`'s `parseFloat` handling of non-numeric input (Bug #5).
- Outside `features/`, this slice has **zero automated tests**: `modules/` (AiEnrichment, HeadlessCms/fieldType, Settings, Enterprise, SecurityPermissions, FileUrlFormatter), `presentation/config`, `presentation/Settings`, `presentation/FileManager` (including the paste-to-upload path and the settings-driven `maxSize` gate), `presentation/hooks`, and `presentation/fieldRenderers` have no `*.test.ts` files at all, despite containing the settings-validation gap, the paste-bypass gap, and the AI re-enrichment streaming state machine (`ReenrichWithAiPresenter`).

## Recommendations
1. Fix the upload feature's two concrete bugs together: give `uploadMany` a per-file `AbortController` (Bug #1) and stop matching batch results by filename — have the SDK's `createFiles`/`createFile` echo back a caller-supplied id (or switch to submission-order zipping) so results attach to the correct job even with duplicate filenames (Bug #2); add tests for both before wiring a "cancel one file" button to `abort()`.
2. Close the client-side validation gap: route pasted files through the same `accept`/`maxSize` check `BrowserFilePicker` applies (Bug #4), and add a numeric/range validator (plus min ≤ max) to the two settings fields before they reach `parseFloat` (Bug #5) — both are silent-failure gaps in exactly the "file type/size validation client vs server" area this audit was asked to focus on.
3. Gate `DeleteFileRepository`'s cache invalidation on the actual boolean result instead of only on `isFail()` (Bug #3), and remove the duplicate `GetFileFeature` registration in `app.tsx` (Bug #6).
