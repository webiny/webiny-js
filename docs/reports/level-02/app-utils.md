# @webiny/app-utils

> Level 2 · commit 19c9ca1b91 · audited 2026-09-26

## Summary
`@webiny/app-utils` provides small, namespace-scoped MobX-observable admin-UI building blocks — `LoadingRepositoryFactory`/`MetaRepositoryFactory` (cached-by-namespace singleton repositories for per-list loading flags and pagination meta) consumed by `app-website-builder` and `app-aco` — plus an entirely separate, unexported and unconsumed `features/List` DI-feature subsystem and an unconsumed `Sorting` domain model. The actively-used half of the package (the `fta/` tree) works but has a real caching bug shared by all three of its repository factories, and a fragile cursor-arithmetic method; the rest of the package (roughly half its files) is dead code with zero test coverage anywhere in the package.

## Public API
- `loadingRepositoryFactory` / `LoadingRepositoryFactory.getRepository(namespace?)` (`packages/app-utils/src/fta/Domain/Repositories/Loading/LoadingRepositoryFactory.ts:3,21`) — used by `packages/app-website-builder/src/features/pages/shared/feature.ts` and `packages/app-aco/src/features/folders/feature.ts`, always called with an explicit namespace today.
- `metaRepositoryFactory` / `MetaRepositoryFactory.getRepository(namespace?)` (`packages/app-utils/src/fta/Domain/Repositories/Meta/MetaRepositoryFactory.ts:3,21`) — used by `app-website-builder`'s shared page feature; `MetaRepository.increaseTotalCount`/`decreaseTotalCount` are each called from one place (`DeletePageRepository.ts`, `DuplicatePageRepository.ts`) but nothing in the repo currently calls `.set()` on that specific repository instance, so its `cursor` field is always the empty default in current usage.
- `Meta`/`MetaDTO`/`MetaMapper`, `ILoadingRepository`/`IMetaRepository` types — consumed as types by `app-website-builder` and `app-aco`.
- `Sorting`/`SortingDTO`/`SortingMapper`/`sortRepositoryFactory`/`ISortingRepository` (`packages/app-utils/src/fta/Domain/**/Sorting*`) — codegraph/grep: no consumers anywhere else in the monorepo.
- `ListFeature` and the whole `features/List/*` subsystem (`packages/app-utils/src/features/List/*.ts`) — not exported from the package barrel (`src/index.ts` only re-exports `./fta/index.js`) and not imported by anything outside the same directory; effectively unreachable.

## Duplication
- jscpd flags `packages/app-utils/src/features/List/LoadingRepository.ts:25-37` as a clone of `packages/app-utils/src/fta/Domain/Repositories/Loading/LoadingRepository.ts:36` — this is the two independent, never-reconciled `LoadingRepository` implementations described under Dead code below; one (`fta/...`) is the real, consumed one, the other (`features/List/...`) is dead.
- The `getCacheKey` bug (Bug #1) is duplicated verbatim across the three factory classes (`LoadingRepositoryFactory`, `MetaRepositoryFactory`, `SortingRepositoryFactory`); a shared base class or helper would have fixed it in one place instead of three.

## Dead code
- The entire `packages/app-utils/src/features/List/` directory (`abstractions.ts`, `feature.ts`, `FilterFeature.ts`, `LoadMoreFeature.ts`, `LoadingRepository.ts`, `ListQueryParamsRepository.ts`, `SearchFeature.ts`, `SortFeature.ts` — 8 files, ~250 lines) is unreachable: it is not re-exported from `src/index.ts` (which only exports `./fta/index.js`), and grep across the whole monorepo shows no import of any of its symbols outside the directory itself. It duplicates the loading-state concept already implemented (and actually used) by `fta/Domain/Repositories/Loading/LoadingRepository.ts` with a slightly different API (`ILoadingRepository.get()` returning a plain object vs. the `fta` version's `Map`-backed one with an extra `getActiveLoadings()` method).
- `Sorting`/`SortingDTO`/`SortingMapper`/`SortingRepository`/`SortingRepositoryFactory`/`ISortingRepository`/`sortRepositoryFactory` (`packages/app-utils/src/fta/Domain/{Models,Repositories}/Sorting/*`) have no consumers anywhere in the monorepo outside this package (codegraph/grep: no matches). Exported from the package barrel but unused.

## Convention issues
`packages/app-utils/src/features/List/abstractions.ts` bundles eight unrelated abstractions (`BaseListParams`, `ListQueryParamsRepository`, `LoadingRepository`, `ListDataRepository`, `SearchFeature`, `FilterFeature`, `SortFeature`, `LoadMoreFeature`) into one file. This mirrors a pattern seen elsewhere in the codebase (e.g. `app`'s router `abstractions.js`), so it isn't flagged as a hard violation of `one-class-per-file.md` (these are `createAbstraction` constants, not classes), but combined with the fact that this whole subsystem is dead code, it's worth removing rather than fixing.

## Test gaps
The package has zero test files (`find . -iname "*.test.ts"` returns nothing). In particular there is no coverage for: the namespace-based caching in any of the three factories (which would have caught Bug #1), `MetaRepository.increaseTotalCount`/`decreaseTotalCount`'s cursor handling (which would have caught Bug #2), or `ListQueryParamsRepositoryImpl`'s clone/notify/subscribe logic.

## Recommendations
1. Fix the `getCacheKey` fallback in all three factories (`LoadingRepositoryFactory`, `MetaRepositoryFactory`, `SortingRepositoryFactory`) to use a stable default key (e.g. a fixed constant like `"default"`) instead of `Date.now().toString()`, and add a test asserting two no-namespace calls return the same instance.
2. Delete the unreachable `features/List/*` subsystem (8 files) and the unconsumed `Sorting` domain model/repository (7 files) — together they are roughly half the package's source and are exercised by nothing, which just adds maintenance surface and, in the `LoadingRepository` case, active confusion with the real implementation.
3. Add unit tests for the `fta/` repositories that are actually in use (`LoadingRepository`, `MetaRepository`, their factories), especially around `updateMetaOnColumnDeltaChange`'s cursor arithmetic, before any caller starts feeding it real (non-null) cursors.
