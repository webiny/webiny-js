# @webiny/admin-ui — Data display, navigation and overlays

> Level 2 · commit 19c9ca1b91 · audited 2026-09-26

## Summary
This slice covers admin-ui's navigation chrome (`Sidebar`, `Breadcrumbs`, `HeaderBar`, `Tabs`), data-display components (`Tree`, `Accordion`, `DataTable`, `DataList`, `Table`, `List`, `Widget`, `SteppedProgress`, `DynamicFieldset`, `EditableTitle`), and overlay primitives (`Dialog`, `Drawer`, `DropdownMenu`, `Popover`, `Tooltip`, `Toast`). Most components are thin, well-conventioned wrappers around Radix primitives or `@tanstack/react-table`, following the package's Domain/DTO/Formatter/Presenter (MobX) pattern for the two components with real state machines (`Tree`, `SteppedProgress`). Health is generally good, but there is one real, unguarded bug in the Sidebar's per-item id generation that can make pin/expand state collide across menu items, and one logic bug in `useToast`'s action-wrapping check. Test coverage for this slice is very thin: of ~19 folders, only `Tree` and `SteppedProgress` have presenter unit tests; everything else (including the buggy Sidebar and Toast code) is untested.

## Public API
- `Sidebar`, `Sidebar.Menu*` family (`Sidebar/index.ts`) — the main app shell navigation; ~62 files reference it across `app-admin`, `app-admin-ui`, and app packages.
- `Tree` (`Tree/index.ts`), backed by `useTree`/`TreePresenter` — drag-and-drop tree used by folder/page-tree UIs; ~59 references (e.g. `app-page-builder`, `app-headless-cms` folder trees).
- `Accordion`, `Tabs`, `Dialog`, `Drawer`, `DropdownMenu`, `Popover`, `Tooltip`, `Toast`/`useToast` — generic overlay/disclosure primitives, each used broadly across admin apps (Dialog ~278, Tooltip ~67, useToast ~57, Tabs ~56, Drawer ~58 references by grep, approximate).
- `DataTable` (`DataTable/index.ts`) — `@tanstack/react-table`-based table with sorting/resizing/column-visibility; ~22 references, notably `app-aco` and `app-admin`'s generic `Table` components build on top of it.
- `DataList` / `DataListWithSections` (`DataList/index.ts`) — list-with-toolbar layout (search/filters/pagination/multi-select); `DataList` ~21 references, `DataListWithSections` appears to have only 1 external reference.
- `Table`, `List`, `Widget`, `SteppedProgress`, `Breadcrumbs`, `HeaderBar` — presentational building blocks; `HeaderBar` is used by `app-admin-ui`'s `Layout.tsx` and a handful of editor headers (~5 references), `SteppedProgress` is used in ~2 places (wizard-style flows), `Breadcrumbs` in ~17 places.
- `DynamicFieldset` (`DynamicFieldset/index.ts`) — legacy class-based repeating-fieldset renderer; re-exported through `packages/admin-ui/src/exports/admin/ui.ts` and `packages/webiny/src/admin/ui.ts`, but no other package in the monorepo appears to actually use it (see Dead code).
- `EditableTitle` (`EditableTitle/index.ts`) — inline-editable heading; used by `app-headless-cms`'s content model editor header and `app-website-builder`'s page editor top bar (2 consumers).

## Duplication
- `SidebarMenuRootItem.tsx` and `SidebarMenuSubItem.tsx` (and their button counterparts `SidebarMenuRootButton.tsx` / `SidebarMenuSubButton.tsx`) are near-identical implementations of the same menu-item behavior (id generation, pin/expand handlers, icon slotting) duplicated for the "root level" vs "nested level" case — confirmed by jscpd (multiple clones between these file pairs, ~14-64 lines each). This is also why Bug #1 exists in two places instead of one; extracting a shared `useSidebarMenuItem(buttonProps)` hook would fix the bug once and remove the duplication.
- `packages/admin-ui/src/DataList/DataList.tsx` and `packages/admin-ui/src/DataList/DataListWithSections.tsx` share large, near-identical blocks (jscpd flags ~25-30 line clones at the toolbar/`showOptions` section and the scroll-container wrapper). The two components differ mainly in header markup (plain `<Heading>` vs. a bordered section header) but duplicate the loading/empty-state branching and the entire options toolbar (search/select-all/refresh/pagination/sorters/filters/modal/actions) verbatim.
- `packages/admin-ui/src/Dialog/components/Icon.tsx` and `packages/admin-ui/src/Widget/components/Icon.tsx` are byte-for-byte identical except for one prop value (`color={"neutral-strong"}` vs `color={"accent"}`); jscpd also flags a third copy in `Card/components/Icon.tsx` (outside this slice). A single shared `Icon` wrapper parameterized by color would remove three copies of this file.
- `packages/admin-ui/src/Dialog/components/DialogFooter.tsx` and `packages/admin-ui/src/Drawer/components/DrawerFooter.tsx` share a 9-line clone (jscpd), and `Dialog.tsx`/`Drawer.tsx` share a 20-line clone — expected, since `Drawer` is intentionally modeled as a mobile/side-panel variant of `Dialog`, but it means any future fix to one (e.g. accessibility description handling, see the matching `TODO` comments in both files) must be applied to both.

## Dead code
- `DynamicFieldset` (`packages/admin-ui/src/DynamicFieldset/Fieldset.tsx`, exported from `DynamicFieldset/index.ts` and re-exported via `packages/admin-ui/src/exports/admin/ui.ts` / `packages/webiny/src/admin/ui.ts`) has no consumers anywhere else in the monorepo besides those re-export barrels — codegraph/grep shows no import of `DynamicFieldset` outside the package's own export chain. It also has no Storybook stories and no tests. It is a candidate for removal or, if still needed by external plugins, should at least get a story/test to make its expected usage explicit.

## Convention issues
- `DynamicFieldset` is a plain `React.Component` class using an internal render-prop/mutable-instance-field pattern (`this.header`, `this.rows`, etc. set as a side effect of calling `children(...)` during render), which is inconsistent with the rest of this slice's convention of Domain + Formatter + MobX Presenter (as used by `Tree` and `SteppedProgress`). This isn't necessarily wrong (it may predate the convention), but it's the only class component in the audited folders and has no accompanying `.mdx`/story documentation the way the newer components do.
- `DataList` and `Table` (this package's low-level `Table/Table.tsx`, not `DataTable`) have no `.stories.tsx`, unlike every other component in this slice; `EditableTitle` and `DynamicFieldset` also lack stories.

## Test gaps
- Across all 19 folders in this slice, only `Tree/presenters/TreePresenter.test.ts` and `SteppedProgress/presenters/SteppedProgressPresenter.test.ts` exist. Everything else — `SidebarProvider`'s pin/expand/localStorage-style state machine, the `menuItemId` generation implicated in Bug #1, `Tree`'s drag-and-drop handlers in `useTree.ts` (`handleDrop`, `canDrop`, `sort`), `DataList`/`DataListWithSections` toolbar wiring, `DataTable`'s column-resizing and column-visibility logic, and `useToast`'s action/title/description wrapping (implicated in Bug #2) — has no unit test coverage at all.
- In particular, the pin/unpin and expand/collapse behavior in `Sidebar` (the most complex stateful logic in this slice) is entirely exercised only through Storybook, with no assertions that pinning one item doesn't affect another — which is exactly the scenario Bug #1 breaks.

## Recommendations
1. Fix `menuItemId` generation in `SidebarMenuRootItem.tsx`/`SidebarMenuSubItem.tsx` to use a stable, caller-supplied id (or a hash of the item's position/label prop that doesn't silently collapse `ReactNode` labels to a constant string), and add a regression test for two same-level items with JSX labels.
2. Extract the duplicated Root/Sub item and button logic into a single shared hook/component; this removes ~4 jscpd clone pairs and ensures the id-generation fix only has to be made once.
3. Add presenter/hook-level tests for `SidebarProvider` (pin/expand state) and `useToast` (title/description/action wrapping, including the `getActions` branch implicated in Bug #2), since these are the two areas with real behavioral logic and zero current coverage.
