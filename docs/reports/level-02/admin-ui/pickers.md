# @webiny/admin-ui — Pickers and inputs with complex state

> Level 2 · commit 19c9ca1b91 · audited 2026-09-26

## Summary
This slice covers admin-ui's "complex state" form controls: `AutoComplete`/`MultiAutoComplete`, `Select`/`MultiSelect`, `Tags`, `FilePicker`/`MultiFilePicker`, `DatePicker`/`Calendar`, `IconPicker`, `ColorPicker`, `ImageEditor`, and the underlying `Command` list-palette primitive they share. Most of these components (AutoComplete, MultiAutoComplete, Select, Tags, FilePicker, MultiFilePicker, IconPicker, ColorPicker) follow the same Model-View-Presenter convention used across the whole package: a `useXxx` hook wires an observable `XxxPresenter` (mobx `makeAutoObservable`) through `autorun`/`useState` into a `vm`, with a `Command`-based option list underneath. `MultiSelect`, `DatePicker`/`Calendar`, and `ImageEditor` are the exceptions — they use plain React state instead of a presenter. Overall health is solid: no functional bugs were found in the code read, the AutoComplete/MultiAutoComplete/Select/Tags family has real presenter unit tests, and the architecture is consistent enough to reuse. The one concrete, fixable issue is that the small generic `ListCache<T>` helper (add/remove/update/find over an observable array) is copy-pasted byte-for-byte into three separate files in this slice (`AutoComplete/domains/ListCache.ts`, `MultiAutoComplete/domains/ListCache.ts`, `IconPicker/domains/ListCache.ts`) instead of living in one shared place — any higher-level package building its own searchable/observable list should look here rather than reimplementing it, and admin-ui itself should consolidate to one copy.

## Public API
- `AutoComplete` / `MultiAutoComplete` (`AutoComplete/AutoComplete.tsx`, `MultiAutoComplete/MultiAutoComplete.tsx`) — form fields; consumed by `app-aco` (`UsersTeamsMultiAutocomplete`), `app-file-manager` (tags field), `app-headless-cms` (permissions editor), and re-exported from `packages/webiny/src/admin/ui.ts`.
- `Select` / `MultiSelect` (`Select/Select.tsx`, `MultiSelect/MultiSelect.tsx`) — generic dropdown selects, used throughout the admin app's forms (headless-cms, page-builder, form fields, etc.).
- `Tags` (`Tags/Tags.tsx`) — free-form tag input; consumers include `app-admin`'s `LoginScreen`/`Navigation` and file-manager tagging UI.
- `FilePicker` / `MultiFilePicker` (`FilePicker/FilePicker.tsx`, `MultiFilePicker/MultiFilePicker.tsx`) — single/multi file-reference pickers with `.Preview.{Image,RichItem,TextOnly}` static sub-components; used by `app-file-manager` and `app-website-builder`.
- `DatePicker` (`DatePicker/DatePicker.tsx`) — a discriminated-union component (`type: "date" | "time" | ... | "multipleYears"`) dispatching to 11 internal picker variants; `Calendar` (`Calendar/Calendar.tsx`) is the underlying `react-day-picker` wrapper it (and others) render into a `Popover`.
- `IconPicker` / `ColorPicker` — form pickers over a fixed option/icon list, same presenter shape as Select.
- `ImageEditor` (`ImageEditor/ImageEditor.tsx`) — crop/hotspot/alt/caption dialog; consumed by `app-file-manager` (`EditImage`, `CmsImageEditorDialog`) and `app-website-builder`'s `FileInput` (~3 call sites via codegraph).
- `Command` and its `domain/CommandOption*` types are the shared building blocks (`CommandOption`, `CommandOptionFormatted`, `CommandOptionFormatter`) that AutoComplete/MultiAutoComplete/Select/IconPicker/ColorPicker all build their option lists on top of.

## Duplication
- **`ListCache<T>` triplicated verbatim** — `packages/admin-ui/src/AutoComplete/domains/ListCache.ts:24-78`, `packages/admin-ui/src/MultiAutoComplete/domains/ListCache.ts:24-78`, and `packages/admin-ui/src/IconPicker/domains/ListCache.ts` (confirmed via jscpd: `AutoComplete/domains/ListCache.ts` and `MultiAutoComplete/domains/ListCache.ts` are a 78-line, byte-identical clone; `IconPicker/domains/ListCache.ts` clones the same 78 lines against `MultiAutoComplete`'s copy). Same class name, same generic `add/update/remove/getItems/getItem` API, three separate files. High confidence — this is a straightforward extract-to-shared-module fix (e.g. into `Command/domain` or a package-level `internal/` folder), not a "these happen to look similar" case.
- **AutoComplete vs MultiAutoComplete — near-total presenter/component duplication.** jscpd flags ~10 separate clone pairs between the two folders: `AutoCompletePresenter.ts:78-91` / `MultiAutoCompletePresenter.ts:88-101`, `AutoCompleteListOptionsPresenter.ts` (three clone spans against `MultiAutoCompleteListOptionsPresenter.ts`), `AutoCompleteList.tsx` / `MultiAutoCompleteList.tsx` (three spans), `AutoCompleteInputIcons.tsx` / `MultiAutoCompleteInputIcons.tsx` (two spans), and `AutoComplete.tsx:29-49` / `MultiAutoComplete.tsx:29-49`. Plus their test suites duplicate large blocks internally (`AutoCompletePresenter.test.ts` and `MultiAutoCompletePresenter.test.ts` each have many self-referential jscpd hits, and cross-file hits between the two test files, e.g. `AutoCompletePresenter.test.ts:32-57` / `MultiAutoCompletePresenter.test.ts:75-100`). This is the expected cost of the "single vs multi" variant pattern used across the package, but the amount of near-identical logic (list options presenter, list rendering, input icons) suggests a shared base presenter/component could absorb most of it, the way `MultiAutoCompleteListOptionsPresenterWithUniqueValues` already wraps the base list-options presenter.
- **Select family**: `MultiSelect.tsx:24-44` and `IconPicker.tsx:24-44`/`ColorPicker.tsx:24-44` duplicate `Select.tsx:24-44`'s label/description/error/note wrapper markup almost verbatim (jscpd, ~15-16 line spans each). This wrapper (label + description + primitive + error + note) is repeated per form component rather than factored into one `FormField`-style wrapper.
- **`useXxx` hook boilerplate**: `useAutoComplete`, `useMultiAutoComplete`, `useSelect`, `useTags`, `useFilePicker`, `useMultiFilePicker`, `useIconPicker`, `useColorPicker` all repeat the same `useMemo(params) → useMemo(new Presenter()) → useState(vm) → useEffect(init) → useEffect(autorun)` shape (jscpd flags several of these against each other and against `Toggle/useToggle.ts`, which is outside this slice but the same pattern). Not a bug, but it's boilerplate that could be a single generic `usePresenter(paramsFactory, presenterFactory)` hook.
- **`DatePicker` variant components**: `MultipleYearsPicker.tsx`/`YearPicker.tsx` (22-line clone), `MultipleDatesPicker.tsx`/`MultipleYearsPicker.tsx` (12-line clone), `MonthPicker.tsx`/`MultipleMonthsPicker.tsx` (16-line clone), `DateRangePicker.tsx`/`YearPicker.tsx` (11-line clone) — each of the 11 picker variants re-implements its own `open` state, `handleOpenChange`, and `toDateStr` helper (the latter duplicated verbatim in both `DateRangePicker.tsx:10` and `MultipleDatesPicker.tsx:10`) instead of sharing a small `usePickerPopover`/`toDateStr` utility.
- **`ImageEditor/geometry.ts`** — the per-axis "position/width/height/objectFit/objectPosition" style object is built twice: once inline in `getPreviewStyles` (lines 115-128) and once in the local `imageStyle` helper inside `getCroppedImageRenderStyles` (lines 158-169). The duplication is acknowledged in a comment ("See getPreviewStyles") but was never actually factored out. Low severity — 12 lines, well-contained.
- **FilePicker preview SVG assets** — jscpd also flags the 8 file-type preview icons (`xls.svg`, `xlsx.svg`, `pdf.svg`, etc. under `FilePicker/primitives/components/previews/assets/`) as "clones" of each other; these are just visually-similar static SVGs, not a real code-duplication concern.

## Convention issues
`MultiSelect` breaks from its siblings' architecture without an obvious reason: every other component in this slice (`AutoComplete`, `Select`, `Tags`, `FilePicker`, `IconPicker`, `ColorPicker`) has a `primitives/presenters` + `domains` split with a mobx presenter class, while `MultiSelect` (`MultiSelect/primitives/MultiSelectPrimitive.tsx`) manages `value`/`onChange` with plain `useState`/`useCallback` and has no `presenters`/`domains` folder at all. It's not wrong — the component is simpler — but it means `MultiSelect` doesn't share the `ListCache`/`CommandOption` machinery the rest of the pickers use, which is part of why its options list (`MultiSelectContent`) re-implements filtering/rendering instead of reusing `Command`. `MultiSelectPrimitive.tsx` also defines three components (`MultiSelectTrigger`, `MultiSelectContent`, `DecoratableMultiSelectPrimitive`) in one file, whereas `SelectPrimitive.tsx` keeps a comparable split but the rest of the slice tends toward one component per file under `primitives/components/`.

## Test gaps
- **No unit tests at all**: `DatePicker`, `Calendar`, `IconPicker`, `ImageEditor`, `Command`, and `MultiSelect` have zero `.test.ts(x)` files in this slice. `DatePicker` in particular has 11 branching variants (date/time/dateTimeLocal/dateTimeTz/month/week/year/dateRange/multipleDates/multipleMonths/multipleYears) with real formatting/parsing logic in `utils/dateHelpers.ts` and no automated coverage for any of it.
- `ImageEditor`'s `geometry.ts` (the crop/hotspot → CSS math shared between the live preview strip and the crop editor) has no tests despite being explicitly called out in its own header comment as needing to stay in sync with a separate SDK copy — a natural place for a regression test given two independent implementations must agree.
- `ColorPicker` has one test file but it's worth confirming (not verified in this audit) it covers the presenter, not just the primitive shell.

## Recommendations
1. Consolidate the three identical `ListCache<T>` copies (`AutoComplete`, `MultiAutoComplete`, `IconPicker`) into a single shared module — this is the cleanest, lowest-risk win in the slice and directly reduces the biggest jscpd hit.
2. Add unit tests for `DatePicker`'s `dateHelpers.ts` (format/parse round-trips for all 11 variants) and for `ImageEditor/geometry.ts` (crop/hotspot → style math), since both are pure-logic modules with zero coverage today and non-trivial edge cases (clamping, zero-size crops, aspect-ratio locking).
3. Factor the repeated `useXxx` presenter-hook boilerplate and the repeated Select/IconPicker/ColorPicker/MultiSelect label+description+error+note wrapper markup into shared helpers, to shrink the AutoComplete/MultiAutoComplete duplication surface and make future single/multi variants cheaper to keep in sync.
