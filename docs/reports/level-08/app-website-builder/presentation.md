# @webiny/app-website-builder — Presentation

> Level 8 · commit 19c9ca1b91 · audited 2026-09-26

## Summary
This slice (`packages/app-website-builder/src/presentation`, ~11.2k lines) is the admin-facing MobX-presenter layer for pages, redirects, A/B experiments, navigation-framework config export, and language/permission helpers: page list/trash/create/translate/settings, the page editor's autosave and revisions UI, the redirects list (create/edit), and the experiments editor/manager/form trio that lets editors run on-page A/B tests. It follows the package-wide Presenter/DataSource DI pattern consistently and correctly reuses `@webiny/app-aco`'s `FolderTreePresenter`, `@webiny/app-admin`'s `ListPresenter`/`FormModelFactory`/`Worker`, and `@webiny/languages`'s `useLanguages` rather than reimplementing them. Overall health is good — the experiments editor presenter is a model example of a correctly-guarded async load (explicit `loadToken`) — but `PageEditor.tsx`'s own page-fetch effect has no equivalent guard, so a slow page load can silently overwrite a newer one. Test coverage is very thin: of ~11.2k lines, only `CreatePage` has a test file.

## Public API
This slice has no package-level public API of its own (its presenters/components are consumed internally, by the package's `presentation/pages`, `presentation/redirects`, and `presentation/experiments` route entry points, and by `~/BaseEditor`'s editor-config registration). Notable internal exports and their approximate consumers (via codegraph/grep):
- `PageListPresenter`, `RedirectListPresenter` (`pages/PageList/PageListPresenter.ts`, `redirects/RedirectList/RedirectListPresenter.ts`) — DI-registered per-route presenters; each has exactly the two expected callers (its own `feature.ts`/`index.ts`), consumed by the corresponding `PagesList`/`RedirectsList` route components.
- `ExperimentsEditorPresenter` (`experiments/ExperimentsEditor/ExperimentsEditorPresenter.ts`) — the single source of truth for a page's experiments, injected into `ExperimentsManagerPresenter` (drawer) and the preview toolbar; ~2 direct consumers within this slice.
- `PageAutoSave`, `PageEditor` (`pages/PageEditor/PageAutoSave.tsx`, `pages/PageEditor/PageEditor.tsx`) — mounted by the page-editor route; `PageAutoSave` is the sole place `updatePage` is invoked for in-editor autosave.

## Duplication
- **Pages vs. Redirects list stack is a near-complete parallel implementation**, per the jscpd report, e.g.:
  - `pages/PageList/configs/Browser/{Filter,BulkAction,FolderAction,FiltersToWhere}.tsx` vs. `redirects/RedirectList/configs/Browser/{Filter,BulkAction,FolderAction,FiltersToWhere}.tsx` — `Filter.tsx` is byte-identical for its full 57 lines; `FolderAction.tsx`/`FiltersToWhere.tsx` are fully duplicated (14–16 lines each); `BulkAction.tsx` shares 3 separate ~10–25-line blocks with the Pages version and with its own sibling `Filter.tsx`.
  - `pages/PageList/components/{DocumentList,PagesList,Table/Table}.tsx` vs. `redirects/RedirectList/components/{DocumentList,RedirectsList,Table/Table}.tsx` — `DocumentList.tsx` shares two large blocks (64 and 22 lines) plus overlapping blocks with `Empty.tsx`; `PagesList.tsx`/`RedirectsList.tsx` share their imports header and mount/dispose effect (9 + 12 lines).
  - `RedirectListPresenter.ts` and `PageListPresenter.ts` (both read above) hand-roll the same "wrap `ListPresenter`+`FolderTreePresenter` behind a route-scoped presenter with a folder-selection `reaction` and manual dispose" shape independently, rather than sharing one generic list-presenter base — the concrete duplication is smaller (jscpd didn't flag the whole class) but the design is repeated by hand in both files.
  - This is consistent with what the redirects feature (out of this slice) is: a near-clone of the pages feature for a different domain object. A shared `DocumentListPresenter`/generic `Browser` config factory parameterized by domain type would remove most of this.
- `CreateRedirectPresenter.ts`/`EditRedirectPresenter.ts` share a 44-line block (`RedirectList/CreateRedirectPresenter.ts:55-98` vs. `RedirectList/EditRedirectPresenter.ts:83-126`) — the loading-state/try-finally/form-submit wrapping around `updateRedirectUseCase`/`createRedirectUseCase` is copy-pasted rather than factored into a shared "submit with loading state" helper.
- `navigation/NextjsConfig/{NextjsConfigRepository,NextjsConfigPresenter}.ts` vs. `navigation/NuxtConfig/{NuxtConfigRepository,NuxtConfigPresenter}.ts` — 21 and 22 identical lines respectively; both frameworks' config generation follows the same repository/presenter shape and could share a generic base parameterized by framework.
- `pages/bulkActions/Bulk{Publish,Unpublish,Delete,Duplicate}Presenter.ts` share a 9-line block each with `BulkUnpublishPresenter.ts` — the same small constructor/init boilerplate repeated four times.
- Minor: `PageEditor/TopBar/PublishButton.tsx` and `PageList/hooks/usePublishPageConfirmationDialog.tsx` share a 14-line block (the publish-confirmation copy/logic), and `Revisions/RevisionsList.tsx`/`TopBar/RevisionsMenu.tsx` share a 13-line block (revision-loading effect), consistent with both being independent front-ends onto the same "load and list page revisions" behaviour.
- `experiments/ExperimentsEditor/components/ExperimentPreviewToolbar.tsx:77-93` and `experiments/ExperimentsManager/components/ExperimentCard.tsx:116-132` share a 17-line block (bucket/variant rendering), a smaller instance of the same "not extracted into a shared bucket-list component" pattern.
- `BaseEditor/defaultConfig/Content/Preview/useIframeUrl.ts:23-43` and `pages/PageList/hooks/usePagePreviewLink.ts:32-52` share 21 lines (outside this slice's own boundary but touching it) — the preview-iframe URL-building logic is duplicated between the editor's live preview and the page list's "preview" action.

## Dead code
- `pages/PageEditor/EditorStateDebugger.tsx` exports `EditorStateDebugger`, which is not imported anywhere else in `app-website-builder` (grep of the whole package `src` tree finds only its own definition file); codegraph confirms no render-site caller. It looks like a developer debug panel (dumps document history/snapshots/changes) that was never wired into `DefaultPageEditorConfig`/`PageEditorConfig`.

## Convention issues
- `pages/PageEditor/PageSettings/PageSettingsPresenter.ts:171` exports the implementation as `PageSettingsPresenterRegistration` instead of `PageSettingsPresenter`, breaking the "export name matches abstraction name" DI convention followed everywhere else in this slice (`PageListPresenter`, `RedirectListPresenter`, `ExperimentsEditorPresenter`, `ExperimentFormPresenter`, etc. all export under the exact abstraction name). `feature.ts:3` has to import it under its odd name and alias the abstraction as `PresenterAbstraction` to avoid a collision, which is a symptom of the same naming slip rather than a stylistic choice.

## Test gaps
- Of the entire ~11.2k-line slice, only `pages/CreatePage/CreatePage.test.ts` exists. None of the following have any unit coverage: `PageListPresenter`/`RedirectListPresenter` (folder-filter `reaction`, dispose), `ExperimentsEditorPresenter`'s `loadToken`-guarded async loads and `activate`/`deactivate`/`createExperiment` sequencing, `ExperimentsManagerPresenter`'s per-card variant loading, `ExperimentFormPresenter`'s weight-rebalancing math (`rebalance`/`evenSplit`, which has real edge cases around remainder distribution), and the `PageEditor.tsx` page-loading effect where Bug #1 above lives — a regression test asserting "navigating away during an in-flight page load does not clobber the newer page" does not exist and would have caught it.

## Recommendations
1. Fix `PageEditor.tsx`'s page-load effect (Bug #1) with the same `loadToken`/ignore-flag pattern already used correctly in `ExperimentsEditorPresenter.loadSelectedExperiment` — this is the highest-risk item since it can misattribute autosave writes to the wrong page.
2. Extract the Pages/Redirects "document list" duplication (Browser configs, `DocumentList`/`*List`/`Table` components, and the presenter shape) into one generic, domain-parameterized implementation; this is the largest and most mechanical duplication in the slice and the risk of the two copies drifting (as `Filter.tsx` and `BulkAction.tsx` already show subtly different variants) will only grow.
3. Replace `PageAutoSave.tsx`'s bare lodash `debounce` with either an awaited/promise-aware debounce wrapper or a state update driven directly off the `updatePage` promise, so the `autoSaving` indicator reflects the real save lifecycle (Bug #2), and rename `PageSettingsPresenterRegistration` to `PageSettingsPresenter` for DI-naming consistency.
