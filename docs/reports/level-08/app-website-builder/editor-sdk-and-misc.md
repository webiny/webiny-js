# @webiny/app-website-builder — Editor SDK, input renderers and misc

> Level 8 · commit 19c9ca1b91 · audited 2026-09-26

## Summary
This slice covers the admin-side editor engine (`editorSdk/`: `Editor`, `CommandBus`, `State`/`StateWithHistory`/`EditorHistory`, `executeOnChange` and the `$`-prefixed imperative element commands), the editor↔preview `postMessage` bridge (`DocumentEditor/ConnectEditorToPreview.tsx`), the sidebar input renderers (`inputRenderers/`), the e-commerce resource-picker integration (`ecommerce/`), lightweight domain models (`domain/Page`, `domain/PageRevision`, `domain/Redirect`), small shared helpers, and misc admin modules/wiring (`modules/`, `Extension.tsx`, `routes.ts`, `constants.ts`). The postMessage channel itself is correctly origin-scoped on the admin side (uses the iframe's actual `src` origin, not `"*"`), so no vulnerability was found there. The most significant issue is a confirmed functional bug: undo/redo never propagates document patches to the live preview iframe, so the preview visibly desyncs from the editor state after any undo/redo. There is also a reimplementation of `@webiny/app-admin`'s `ListCache` with reversed upsert semantics (stale data wins over fresh data), and near-zero automated test coverage across this whole slice (only one test file, for `PagePath`).

## Public API
- `Editor` (`editorSdk/Editor.ts`) — the imperative/observable editor engine wrapping document + editor UI state and the command bus. Widely used throughout `app-website-builder`'s presentation layer (PageEditor, sidebar, BaseEditor); re-exported via `DocumentEditor/DocumentEditor.tsx`.
- `executeOnChange` / `applyAncestorUpdates` (`editorSdk/utils/executeOnChange.ts`) — runs `manifest.onChange`/`onDescendantChange` handlers; per codegraph, ~10 internal callers (`$createElement`, `$deleteElement`, `$cloneElement`, `useInputValue`, etc.), no tests within 3 caller hops.
- `$updateElementInputs`, `$previewElementInputs`, and the other `$`-prefixed commands (`editorSdk/utils/index.ts` barrel) — the public imperative command API used by component manifests to mutate/preview element inputs.
- `EcommerceIntegration` (`ecommerce/EcommerceIntegration.tsx`) — 4 callers found by codegraph (`extensions/saleorEcommerce`, `extensions/sampleEcommerce`, this package's `exports/admin/website-builder.ts`, `packages/webiny/src/admin/website-builder.ts`); no tests within 3 caller hops.
- Input renderers (`TextInput`, `TextareaInput`, `ColorPickerInput`, `SelectInput`, `NumberInput`, `BooleanInput`, `ObjectInput`, `SlotInput`, `GridLayoutInput`, `FragmentSelectorInput`, `FileInput`, `LexicalInput/*`) — registered against `ElementInput.Renderer` and consumed by the sidebar/element-settings UI.
- `Page`, `Redirect`, `PageRevision` domain classes and their DTO mappers — consumed by the `features/` and `presentation/` layers of this same package (outside this slice).
- `Extension` (`Extension.tsx`) — top-level admin extension wiring (routes, menus, permissions, feature registration).

## Duplication
- `editorSdk/utils/$previewElementInputs.ts:15-55` and `editorSdk/utils/$updateElementInputs.ts:16-56` — jscpd-flagged 41-line clone. Both re-derive `breakpointNames`, `baseBreakpoint`, `inputsAst`, `rawBindings`, `elementFactory`, `resolvedBindings`, and `deepInputs` identically before diverging (preview-only JSON patch vs. `executeOnChange` + document update). Should share a `resolveDeepInputsForElement(editor, elementId)` helper.
- `domain/Page/Page.ts:73-91` and `domain/Redirect/Redirect.ts:52-70` — jscpd-flagged; `createLocation`/`createIdentity` are byte-for-byte identical in both classes. Candidate for a shared base class or free function.
- `domain/PageRevision/ListCache.ts` is a near-verbatim reimplementation of `@webiny/app-admin`'s `ListCache` (`packages/app-admin/src/features/listCache/ListCache.ts`) — same interfaces (`IListCachePredicate`, `IListCacheItemUpdater`, `IListCache`), same method set, but hardcodes the union key to `"id"` (no `keyField`/`setItems`) and has the reversed-precedence bug described above (Bug #2). This duplicates a package that is a listed dependency of this slice and should be replaced by importing `@webiny/app-admin`'s `ListCache`, matching what `domain/Page/PagesCacheFactory.ts` already does.
- `inputRenderers/TextInput.tsx`, `TextareaInput.tsx`, `ColorPickerInput.tsx` — jscpd-flagged pairwise clones (~21 lines each); all three define identical `commitValue`/`previewValue` closures over `onChange`/`onPreviewChange`. A shared `useCommitAndPreviewValue(onChange, onPreviewChange)` hook would remove the repetition (likely also applies to `NumberInput`/`BooleanInput`, not flagged by jscpd but visually similar — not independently verified).
- `inputRenderers/FragmentSelectorInput.tsx:27-39` and `inputRenderers/SelectInput.tsx:12-23` — jscpd-flagged 13-line clone (not read in full; noted from the jscpd report only).
- `ecommerce/createResourcePicker.tsx` and `ecommerce/createResourceListPicker.tsx` — near-identical factory functions (same `onChange` wrapper, same wrapper `<div>`+`FormComponentLabel`), differing only in which picker component they render.
- `Extension.tsx:52-71` — jscpd flagged this file as self-similar (`<RegisterFeature feature={...} />` lines); this is a benign consequence of the repetitive-but-necessary feature-registration pattern, not a real duplication problem.
- Cross-folder (only the in-slice side is mine): `modules/shared/FolderCellName.tsx:13-36` duplicates `presentation/redirects/RedirectList/components/Table/Cells/CellName.tsx:54-77` (out of this slice) — same icon-selection + label-with-truncate-and-underline pattern.
- Cross-folder (only the in-slice side is mine): `ecommerce/components/toTitleCaseLabel.ts` and `shared/toTitleCaseLabel.ts` are both flagged as clones of `BaseEditor/defaultConfig/Sidebar/StyleSettings/Groups/Background/toTitleCaseLabel.ts` (out of this slice); since both match the same external file, they are effectively duplicates of each other too — this package has at least three copies of the same 10-line title-casing helper.

## Dead code
- `packages/app-website-builder/src/modules/AbTesting.tsx` (`AbTesting` component) — its only reference anywhere in the package is a commented-out `{/*<AbTesting />*/}` in `Extension.tsx:61`; no other file imports it (confirmed by repo-wide grep). The component itself still wires up four `RegisterFeature`s for experiments, so this is a sizeable disabled feature left in the tree rather than a trivial unused export.

## Convention issues
- `domain/PageRevision/ListCache.ts` violates the "no reimplementation of lower-level utilities" principle called out in `@webiny/app-admin`'s own summary risk area — it duplicates that package's `ListCache` wholesale instead of importing it, unlike the sibling `domain/Page/PagesCacheFactory.ts`, which correctly imports `@webiny/app-admin/features/listCache`.
- `ecommerce/EcommerceIntegration.tsx:102-108` uses a namespace (`export namespace EcommerceIntegration`) merged onto the component via `Object.assign`, which is the DI/namespace-type convention used elsewhere in this codebase — no issue here, called out only because it's the correct pattern other files in this slice (e.g. plain domain classes) don't consistently follow for their public types.

## Test gaps
- The entire slice has exactly one test file (`shared/PagePath.test.ts`). None of the following have any test coverage: `editorSdk/Editor.ts`, `CommandBus.ts`, `State.ts`, `StateWithHistory.ts`, `EditorHistory.ts` (including the undo/redo diff bug above, which a basic "undo emits a non-empty diff" test would have caught), `executeOnChange.ts` and all `$`-prefixed commands, all `inputRenderers/*`, all of `ecommerce/*` (including the resource picker/list picker dialogs), and the `domain/*` model/cache classes (including the `ListCache` upsert-precedence bug above).
- `ConnectEditorToPreview.tsx`'s origin-scoping logic (the security-sensitive part of the postMessage bridge) has no test verifying that a message from an unexpected origin is ignored.

## Recommendations
1. Fix `StateWithHistory.undo()`/`redo()` to compute a real diff (e.g. against the pre-undo/redo document state) instead of passing `diff: []`, so the preview iframe stays in sync after undo/redo — add a regression test asserting `PreviewEvents`-style consumers receive a non-empty patch.
2. Replace `domain/PageRevision/ListCache.ts` with the existing `@webiny/app-admin` `ListCache` (as `domain/Page/PagesCacheFactory.ts` already does), fixing the reversed `unionBy` precedence bug as a side effect and removing a full-class duplication.
3. Extract the shared setup logic in `$previewElementInputs.ts`/`$updateElementInputs.ts` and the shared `commitValue`/`previewValue` pattern in the `inputRenderers/*` text-like inputs into common helpers; fix the `PagesIcon`/`PermissionsIcon` duplicate-import bug in `Extension.tsx`; and either remove `modules/AbTesting.tsx` or re-enable it deliberately.
