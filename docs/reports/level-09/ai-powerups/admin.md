# @webiny/ai-powerups — Admin

> Level 9 · commit 19c9ca1b91 · audited 2026-09-26

## Summary
This slice covers `packages/ai-powerups/src/{admin,exports}` (~4.3k lines): the admin-side AI Power-Ups feature set — three "generate content with AI" flows (website-builder page content, headless-CMS entry content via a dialog, and a CMS entry-creation wizard), a "compare entry revisions with AI" dialog, and the settings screens (providers, connections, projects, capabilities, model roles, reader/writer personas). Architecturally it follows the repo-wide DI-feature/MVP pattern (abstraction + gateway + repository + use case + MobX presenter) consistently and correctly delegates to `app-admin`'s `FormModelFactory`/`ToolPipelineRunner`, `app`'s `MainGraphQLClient`, and `app-websockets`'s `useWebsockets` rather than reimplementing them. Overall health is mixed: the three AI-generation flows share a real, confirmed defect — asynchronous responses arrive over a shared websocket channel keyed only by action name, with no request/response correlation, even though the triggering GraphQL mutations return an `id` that is discarded — so a late or duplicate response can silently overwrite form data or create unwanted content after a timeout or a second submission. There is also a security issue in the AI revision-comparison dialog (see Bugs — details withheld, filed privately). There are zero automated tests anywhere in this slice, and the entire "generate content" pattern (dialog + presenter + websocket subscriptions) is triplicated near-verbatim across three files.

## Duplication

This is the same "stale-response" logic bug (see Bugs #1) copy-pasted three times rather than centralized once.

## Convention issues
- `CmsGenerateContentDialog.tsx:59` — leftover `console.log` (see Bugs #2); AGENTS.md/CLAUDE.md conventions call for clean production code paths.
- The three generation flows (Bugs #1 / Duplication) are a clear violation of "one abstraction per file" in spirit — the same request/response correlation concern is reimplemented three times instead of factored into a shared hook/presenter base, which is also why the bug in #1 exists in triplicate rather than being fixed once.
- No other DI-naming, barrel-export, or inline-type violations found in the files read (abstractions consistently use `namespace`-style typed interfaces, e.g. `abstractions.ts` files throughout).

## Test gaps
- Zero test files exist anywhere under `packages/ai-powerups/src/admin` or `src/exports` (`find ... -iname "*.test.*"` returns nothing). Codegraph confirms no tests within 3 caller hops of `GenerateContentFeature` / `CmsGenerateContentFeature`.
- Given the confirmed stale-response bug (Bugs #1), the complete lack of tests around the websocket-driven generation flows and their timeout/cancel/late-message interactions is the most consequential gap — this exact class of bug is easy to regression-test with a fake `useWebsockets` but currently isn't covered at all.
- The AI revision-comparison flow (`CmsCompareEntryRevisionsPresenter`) also has no tests covering its error/timeout paths.

## Recommendations
1. Fix the stale-response race (Bugs #1): thread the mutation's returned `id` through to the websocket message (have the API include it, or filter incoming messages against an in-flight request id held by the presenter) and unsubscribe/ignore messages once a request has timed out, been cancelled, or superseded by a new submission. Do this once, in a shared hook, instead of three separate copies.
2. Remove the triplication identified above by extracting a single `useAiGenerationSubscription`/shared presenter base used by all three "generate content" flows — this also closes the double-listener risk in the two CMS flows and fixes bug #1 in one place instead of three.
3. Add test coverage for the websocket generation flows (success, error, timeout, and — once fixed — stale/duplicate message handling) and for the compare-revisions error path; remove the leftover `console.log` in `CmsGenerateContentDialog.tsx:59`.
