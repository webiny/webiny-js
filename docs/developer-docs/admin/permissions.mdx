# Custom Permissions

This guide shows how to define and register custom permissions for your Webiny application.

## Overview

The permission system lets you:

1. **Define a permission schema** — declare what entities your app manages and what actions users can perform on them.
2. **Register it with `AdminConfig`** — the framework auto-generates the permission UI and handles serialization.

For most apps, you won't write any form UI code at all.

## Quick Start

```tsx
import React from "react";
import { AdminConfig } from "@webiny/app-admin";
import { ReactComponent as PermissionsIcon } from "@webiny/icons/shield.svg";

const { Security } = AdminConfig;

export const SecurityPermission = () => {
    return (
        <AdminConfig>
            <Security.Permissions
                name="store-manager"
                title="Store Manager"
                description="Manage Store Manager permissions."
                icon={<PermissionsIcon />}
                schema={{
                    prefix: "sm",
                    fullAccess: { name: "sm.*" },
                    entities: [
                        {
                            id: "product",
                            title: "Products",
                            permission: "sm.product",
                            scopes: ["full", "own"],
                            actions: [
                                { name: "rwd" },
                                { name: "pw" },
                                { name: "import", label: "Import products" },
                                { name: "export", label: "Export products" }
                            ]
                        },
                        {
                            id: "category",
                            title: "Categories",
                            permission: "sm.category",
                            scopes: ["full"],
                            actions: [{ name: "rwd" }]
                        },
                        {
                            id: "settings",
                            title: "Settings",
                            permission: "sm.settings",
                            scopes: ["full"]
                        }
                    ]
                }}
            />
        </AdminConfig>
    );
};
```

Render `<SecurityPermission />` anywhere in your app's extension component, and the permission UI will appear in the Security module's role editor automatically.

## Schema Reference

The `schema` prop on `Security.Permissions` accepts a `PermissionSchema` object with the following shape:

### `prefix`

A string prefix used to identify permissions belonging to this app. All entity permission names should start with this prefix (e.g., `"sm.product"` for prefix `"sm"`).

### `fullAccess`

An object with a `name` property — the permission emitted when the user selects "Full access":

```ts
fullAccess: { name: "sm.*" }
```

### `entities`

An array of entity definitions. Each entity represents a distinct resource in your app (e.g., Products, Categories, Settings).

| Field | Type | Required | Description |
|---|---|---|---|
| `id` | `string` | Yes | Unique identifier, used for form field naming. |
| `title` | `string` | No | Display title in the UI. Falls back to `id` if omitted. |
| `permission` | `string` | Yes | Permission name emitted for this entity (e.g., `"sm.product"`). |
| `scopes` | `("full" \| "own")[]` | Yes | Available access scopes. |
| `actions` | `ActionDefinition[]` | No | Actions available on this entity. |
| `dependsOn` | `{ entity: string; requires: string }` | No | Dependency on another entity. |

## Actions

Actions define what a user can do with an entity. There are two built-in action types and support for custom boolean actions.

### Built-in: `rwd` (Read / Write / Delete)

```ts
actions: [{ name: "rwd" }]
```

Renders a select dropdown with options: **Read**, **Read + Write**, **Read + Write + Delete**. Serialized as a string on the permission object (e.g., `rwd: "rw"`).

When the access scope is set to "own", `rwd` is automatically set to `"rwd"` (full read/write/delete on own entries).

### Built-in: `pw` (Publish / Unpublish)

```ts
actions: [{ name: "pw" }]
```

Renders a checkbox group with **Publish** and **Unpublish** options. Serialized as a joined string (e.g., `pw: "pu"`).

### Custom Boolean Actions

Any action that isn't `rwd` or `pw` is treated as a custom boolean flag:

```ts
actions: [
    { name: "import", label: "Import products" },
    { name: "export", label: "Export products" }
]
```

Custom actions are grouped under an **"Other Actions"** checkbox group in the UI. Each is serialized as a boolean on the permission object:

```json
{ "name": "sm.product", "rwd": "rwd", "import": true, "export": true }
```

### Combining Actions

You can mix all action types on a single entity:

```ts
{
    id: "product",
    title: "Products",
    permission: "sm.product",
    scopes: ["full", "own"],
    actions: [
        { name: "rwd" },
        { name: "pw" },
        { name: "import", label: "Import products" },
        { name: "export", label: "Export products" }
    ]
}
```

## Access Scopes

Each entity declares which scopes are available:

- `"full"` — Access all entries.
- `"own"` — Access only entries created by the current user. When selected, `rwd` is automatically set to `"rwd"`.

The UI always includes a **"No access"** option in addition to the declared scopes.

```ts
// Users can have full access or only access their own entries.
scopes: ["full", "own"]

// Users can only have full access (or no access).
scopes: ["full"]
```

## Entity Dependencies

Use `dependsOn` to express that one entity requires a specific action on another entity. If the parent entity doesn't have the required action, the child entity is automatically pruned from the serialized permissions.

```ts
entities: [
    {
        id: "product",
        title: "Products",
        permission: "sm.product",
        scopes: ["full", "own"],
        actions: [{ name: "rwd" }]
    },
    {
        id: "review",
        title: "Product Reviews",
        permission: "sm.review",
        scopes: ["full", "own"],
        actions: [{ name: "rwd" }],
        dependsOn: {
            entity: "product",  // ID of the parent entity
            requires: "r"       // Parent must have at least "read" access
        }
    }
]
```

In this example, if "Products" has no access, the "Product Reviews" permission is not emitted — even if the user selected a scope for it.

Dependencies also cascade the `"own"` scope: if a parent entity's scope is `"own"`, all dependent children are forced to `"own"` as well.

## Simple Apps (No Entities)

If your app only needs a binary "full access or no access" permission (no entity-level granularity), omit `entities`:

```tsx
<Security.Permissions
    name="my-app"
    title="My App"
    description="Manage My App access permissions."
    schema={{
        prefix: "ma",
        fullAccess: { name: "ma.*" }
    }}
/>
```

The UI will show only **No access** and **Full access** options.

## Serialization Output

Here's what the permission system produces for different configurations:

**No access** — no permissions emitted for this schema.

**Full access:**
```json
[{ "name": "sm.*" }]
```

**Custom access:**
```json
[
    { "name": "sm.product", "rwd": "rw", "import": true },
    { "name": "sm.category", "rwd": "rwd" },
    { "name": "sm.settings" }
]
```

**Own scope:**
```json
[
    { "name": "sm.product", "own": true, "rwd": "rwd", "export": true }
]
```

Note: when `own` is `true`, the `rwd` field is always set to `"rwd"`.

## Custom Permission UI

If the auto-generated UI isn't sufficient (e.g., you need resource pickers, endpoint selectors, or other custom controls), pass an `element` instead of a `schema`:

```tsx
<Security.Permissions
    name="headless-cms"
    title="Headless CMS"
    description="Manage CMS access permissions."
    icon={<CmsIcon />}
    element={<CmsPermissions />}
/>
```

Your custom component can use the `usePermissionValue` hook to access the current permissions and the `onChange` callback:

```tsx
import { usePermissionValue, usePermissionForm, createPermissionSchema } from "@webiny/app-admin";

const schema = createPermissionSchema({
    prefix: "cms",
    fullAccess: { name: "cms.*" },
    entities: [/* ... */]
});

const CmsPermissions = () => {
    const { value, onChange } = usePermissionValue();
    const { formData, onFormChange } = usePermissionForm(schema, {
        value,
        onChange,
        // Merge extra fields when deserializing permissions into form data.
        deserialize(permissions) {
            return { selectedEndpoints: extractEndpoints(permissions) };
        },
        // Transform the serialized permissions with your custom logic.
        serialize(formData, corePermissions) {
            return applyEndpoints(formData, corePermissions);
        }
    });

    return (
        <Form data={formData} onChange={onFormChange}>
            {/* Your custom form UI */}
        </Form>
    );
};
```

The `usePermissionForm` hook handles the core entity serialization/deserialization; the `serialize` and `deserialize` callbacks let you layer on app-specific logic.

## Props Reference

### `Security.Permissions`

| Prop | Type | Required | Description |
|---|---|---|---|
| `name` | `string` | Yes | Unique identifier for this permission renderer. |
| `title` | `string` | Yes | Display title in the accordion header. |
| `description` | `string` | No | Description shown below the title. |
| `icon` | `ReactElement` | No | Icon shown in the accordion header. |
| `schema` | `PermissionSchema` | One of `schema` or `element` | Auto-generate the permission UI from this schema. |
| `element` | `ReactElement` | One of `schema` or `element` | Render a fully custom permission UI. |
| `system` | `boolean` | No | If `true`, renders before app-level permissions. |
